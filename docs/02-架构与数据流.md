# 02 · 架构与数据流

```
┌─────────────────────────────────────────────────────────────┐

│  AppPrefs（SharedPreferences ⇄ mutableStateOf）                │

│  偏好：SharedPreferences("auto_ledger")                       │
└─────────────────────────────────────────────────────────────┘
```

**约定的两条铁律**

1. **仓库是 `object`，接口一律 `suspend`**：`add / addAll / addImported / load / pageBefore / widgetTotals / rangeTotals / update / delete / deleteByExternalId / clear` 全为挂起函数（`data/LedgerRepository.kt`，192 行），内部 `withContext(Dispatchers.IO)` 直接跑 DAO，已无 `runBlocking`。调用方按上下文分三类：Compose → `rememberCoroutineScope().launch`；广播接收器 / 前台服务 / 小部件 → `goAsync()` 或长驻 `CoroutineScope(SupervisorJob() + Dispatchers.IO)`；`ViewModel` → `viewModelScope`。全仓库唯一保留的 `runBlocking` 在 `LedgerDatabase.kt` 的 `onCreate` 迁移回调（该回调非 suspend，且跑在 Room 初始化线程，不阻塞主线程）。
2. **偏好不走 DataStore**：`AppPrefs` 用 `SharedPreferences` + `mutableStateOf` 双向绑定（get 读 prefs 并回填 state，set 写 prefs 并更新 state），因此 Compose 能直接观察到开关变化。

## 2. 数据模型

### 2.1 Room 实体（`data/LedgerEntity.kt:22`）

```kotlin
@Entity(
    tableName = "Bill",
    indices = [Index("timestamp"), Index(value = ["external_id"], unique = true)],
)
data class LedgerEntry(
    @PrimaryKey val id: Long,                 // 0 表示自增
    val amount: Double,
    val type: String,                          // "expense" | "income" | "other"
    val category: String,
    @ColumnInfo("time_text")  val time: String,      // 展示用文本 "yyyy-MM-dd HH:mm"
    @ColumnInfo("timestamp")  val timeMillis: Long = 0L,  // 排序/聚合用
    @ColumnInfo("remark")     val note: String,
    val source: String,                        // 手动记账/截屏记账/CSV 导入/微信导入
    @ColumnInfo("external_id") val externalId: String? = null,
)
```

等价 DDL（Room v2 生成）：

```sql
CREATE TABLE IF NOT EXISTS Bill (
    id INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
    amount REAL NOT NULL,
    type TEXT NOT NULL,
    category TEXT NOT NULL,
    time_text TEXT NOT NULL,
    timestamp INTEGER NOT NULL,
    remark TEXT NOT NULL,
    source TEXT NOT NULL,
    external_id TEXT
);
CREATE INDEX IF NOT EXISTS index_Bill_timestamp ON Bill(timestamp);
CREATE UNIQUE INDEX IF NOT EXISTS index_Bill_external_id ON Bill(external_id);
```

**双时间字段的意义**：`time_text` 是人读的展示值（用户可手输"08月15日 20:30"这类格式），`timestamp` 是唯一可信的排序/聚合键。`LedgerRepository.normalized()` 在写入前用 `parseTime(time)` 补齐 `timestamp`（为 0 时），`repairTimestamps()` 负责修补历史脏数据——`HomeViewModel.init` 每次打开首页都会跑一次（`viewmodel/HomeViewModel.kt:67-70`）。

### 2.2 `external_id` 与唯一索引的陷阱

唯一索引建在 `external_id` 上，但该列**允许 NULL**。SQLite 的唯一索引视多个 NULL 为互不相同，所以手动记账（`externalId=null`）可以无限插入；导入路径则必须保证 `external_id` 非空且全局唯一（微信单号为 `wx:$order`）。

### 2.3 DAO（`data/LedgerDao.kt`）

| 方法 | 返回 | 说明 |
| --- | --- | --- |
| `observeAll()` | `Flow<List<LedgerEntry>>` | 按 `timestamp DESC` |
| `observePaging(limit, offset)` | `Flow<List<LedgerEntry>>` | 仅取首屏（`limit = pageSize`、`offset = 0`），Room 变更自动推送 |
| `pageBefore(cursorTime, cursorId, limit)` | `suspend List<LedgerEntry>` | 游标分页：`WHERE timestamp < :t OR (timestamp = :t AND id < :id) ORDER BY timestamp DESC, id DESC LIMIT :limit` |
| `importRows()` | `suspend List<ImportRow>` | 导入去重只查 4 列（`external_id/time_text/amount/type`），不再全表读 |
| `sumExpenseOnce(start,end)` / `sumIncomeOnce(...)` / `countRange(...)` | `suspend` | 小部件与提醒的一次性聚合，替代全表 `getAllOnce()` |
| `observeCount()` | `Flow<Int>` | 判断 `hasMore` |
| `observeExpense(start, end)` / `observeIncome(...)` | `Flow<Double>` | 区间合计 |
| `observeTotal(start, end, income: Int)` | `Flow<Double>` | `income=1` 取 `type='income'`，否则取 `type!='income'` |
| `observeBuckets(format, start, end, income)` | `Flow<List<Bucket>>` | 按时间桶聚合 |
| `observeCategories(start, end, income)` | `Flow<List<CategoryAgg>>` | 分类聚合，`ORDER BY total DESC` |
| `getAllOnce()` | `List<LedgerEntry>`（suspend） | 全量读，用于导出/去重/小部件 |
| `insertAll(entries)` | suspend | `@Insert(onConflict = REPLACE)` |
| `update(entry)` | suspend | `@Update` |
| `getMissingTimestamp()` | suspend | `WHERE timestamp = 0` |
| `setTimestamp(millis, id)` | suspend | 补时间戳 |
| `deleteById(id)` / `clear()` | suspend | 删除/清空 |

**时间桶 SQL**（`data/LedgerDao.kt:50-56`）：

```sql
SELECT strftime(:format, timestamp / 1000, 'unixepoch', 'localtime') AS bucket,
       COALESCE(SUM(amount), 0.0) AS total
FROM Bill
WHERE ((:income = 1 AND type = 'income') OR (:income = 0 AND type != 'income'))
  AND timestamp >= :start AND timestamp < :end
GROUP BY bucket ORDER BY bucket
```

要点：
- `timestamp / 1000` 是**整数除法**（列是 INTEGER），秒级精度，避免 SQLite 把毫秒当浮点处理；
- 用 `'localtime'`，因此周/月/年边界必须由 Kotlin 侧按本地时区算好再传入；
- `:format` 由调用方决定，常见为 `'%Y-%m-%d'`（日）、`'%Y-%W'`（周）、`'%Y-%m'`（月）；
- **`income = 0` 的语义是"非收入"**，等于 `expense + other`，所以"其他"（转账/还款）会被算进支出侧统计——这是产品上的有意取舍。

`ReportRepository` 的 `Summary` 口径也一致：`todayExpense`、`monthExpense`、`monthIncome`。

## 3. 迁移链路（三条历史路径）

```
① SharedPreferences("auto_ledger") 里的 JSONArray 旧账单
        │  LedgerDbHelper.migrateFromPrefs()  （onCreate / onOpen 且表空时）
        ▼
② SQLite 旧库 ledger.db · 表 entries（v1，7 列 + 2 索引）
        │  LedgerDatabase.migrateLegacy()   （仅在 auto_ledger.db 文件不存在时跑一次）
        │  runBlocking { dao.insertAll(list) }   // 全仓库唯一保留（迁移回调非 suspend）
        ▼
③ Room 库 auto_ledger.db · 表 Bill（v2）
        │  MIGRATION_1_2：ALTER TABLE Bill ADD COLUMN external_id TEXT
        │                 + CREATE UNIQUE INDEX（LedgerDatabase.kt:36-40）
        ▼
④ 当前 schema（v2）
```

判定细节：
- `LedgerDatabase.get()` 用 `isNew = !context.getDatabasePath("auto_ledger.db").exists()` 决定是否 `migrateLegacy`（`data/LedgerDatabase.kt:23-30`）。**先判再建**，因为 Room 一构建就会创建空库文件，之后再判就永远是"非新库"。
- `migrateLegacy` 以 `OPEN_READONLY` 打开 `ledger.db`，`rawQuery` 读 7 列并映射为 `LedgerEntry`（`LedgerDatabase.kt:46-71`），整体用 `runCatching{...}.getOrDefault(emptyList())` 兜底，旧库损坏不会拖垮首启。
- 旧库 `LedgerDbHelper` 仍保留在代码里但**已不是主存储**，它现在只承担 `migrateFromPrefs` 与旧表结构定义。

> 风险：`MIGRATION_1_2` 里 `CREATE UNIQUE INDEX` 在历史数据 `external_id` 全为 NULL 时安全；一旦旧库被外部写入了重复单号，迁移会抛异常导致 App 首启崩溃（当前无 try-catch）。

## 4. 导入去重算法（`LedgerRepository.addImported`）

```
existing = dao.getAllOnce()
keys = { 每条的 external_id（非空） } ∪ { 每条的 fingerprint() }
新条目 normalized 后：
    filter { keys.add(it.importKey()) }   // set.add 返回 false 即为重复
    .distinctBy { it.importKey() }        // 条目内部也可能重复
insertAll(...)  → LedgerWidgetProvider.requestUpdate()
返回实际新增条数
```

- `fingerprint() = "$time|${"%.2f".format(amount)}|$type"`——**时间用 `time_text` 原串**，因此"08月15日 20:30"与"2026-08-15 20:30"会被视为不同账单（跨批次混格式导入可能漏去重）。
- `importKey() = externalId ?: fingerprint()`。
- 先 `distinctBy` 再插入，但 `filter` 里的 `keys.add` 已经能去重；`distinctBy` 是冗余保险。
- 返回值用于 UI 提示"新增 N 条"。

## 5. 报表聚合（`data/ReportRepository.kt`）

```
observe(context, tab: Int, offset: Int, income: Boolean): Flow<ReportAggregate>
   tab  0 = 周   1 = 月   2 = 年
   offset  0 = 本期，负数 = 向前翻页（-1 上一周/月/年）
```

- 区间计算：周以**周一**为起点，用 `MONDAY - dayOfWeek` 处理周日回绕（周日 `DAY_OF_WEEK=1`，需要减 6 天而非加 1 天）；月/年用 `Calendar` 字段清零。
- `prevStart/prevEnd` 与 `start/end` 等长，用于 `total - previousTotal` 得到环比。
- 同一个 `ReportAggregate` 里并行取四路数据：`trend`（日/周桶，折线）、`bars`（对比桶，柱状）、`categories`（环形/排行）、`total/previousTotal/expense/income`（概览卡）。
- `dayCount = 30` 作为默认刻度数，实际刻度以 `trend.size` 为准。

## 7. 数据流全景（以"截屏记账"为例）

```
磁贴/相册/拍照
   │
   ├─ MediaProjection 路径：ScreenshotRequestActivity（透明页）→ 请求通知权限 → createScreenCaptureIntent → ScreenshotCaptureService(ACTION_CAPTURE)
   ├─ 无障碍路径：ACTION_CAPTURE_ROOT → ScreenshotAccessibilityService.takeScreenshot()
   └─ Root 兜底：RootScreenshot（su -c screencap -p）
        │  Bitmap
        ▼
   VisionHelper.readImageBase64（按 inJustDecodeBounds 缩放） → callVisionModel
        │  POST {baseUrl}/chat/completions（Bearer key，messages 带 image_url data:image/jpeg;base64,...）
        ▼
   ParsedEntry(amount, type, category, time, note)
        │  VisionHelper.postResult → 高优先级通知（含"确认/取消"）
        ▼
   ConfirmEntryReceiver.ACTION_CONFIRM
        │  LedgerRepository.add(source="截屏记账")  → withContext(IO) { insertAll }
        ▼
   Room Bill  → Flow 推送 → 首页/报表/小部件自动刷新
```
