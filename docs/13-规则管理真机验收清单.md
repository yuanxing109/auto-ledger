# 规则管理真机验收清单

> 适用版本：`0.3.0`（`versionCode 4`）及以上。共 9 项，预计 10–15 分钟。

## 前置

- 安装当前 debug 包，并授予短信权限与通知使用权。
- 保持支付宝、微信、短信、银行/其他四个采集开关中至少目标渠道为开启。
- 每次发送新短信时更换金额或测试标记，避免被去重窗口拦掉。

## 验收项

1. **通道基线**：在「设置 → 系统权限体检」确认通知使用权已授权，短信权限为已授权；返回首页后进程仍在前台。
2. **系统规则播种**：进入「设置 → 自动记账 → 高级解析规则 → 系统规则」，应看到恰好 4 条规则，其中「向您支付进账」默认开启。
3. **正常规则试跑**：新建临时短信规则，在「测试此规则」粘贴 `【某公司】向您支付项目服务费19.40元，个税由公司代扣申报`，点「测试匹配」；应显示金额 `19.40` 元、方向 `收入`，页面不崩溃。
4. **乱码防护**：把测试原文改成 `asdf@@乱码999`，再点「测试匹配」；应显示「支出词与收入词一个都没命中，这条规则会跳过」，输入内容仍保留，App 不闪退。
5. **非法正则防护**：把金额正则改成 `(a+)+` 并点「保存」；应在表单内显示正则被拒原因，Dialog 不关闭，App 不闪退；随后恢复成合法正则。
6. **开关即时开启**：新建「验收-通道开关」短信规则，方向选「收入」，金额正则填 `验收标记[甲乙]金额\s*(\d+(?:\.\d{1,2})?)`，收入词填 `验收标记甲，验收标记乙`，分类填 `其他: 验收标记`，保持自动入账开启并保存。
7. **开启后立即生效**：不重启 App，从另一台手机向本机发送 `验收标记甲金额6.66`；应在 5 秒内出现自动记账通知，首页新增 6.66 元收入账单，分类为「其他」。
8. **关闭后立即生效**：回到规则页关闭「验收-通道开关」，不重启 App，再发送 `验收标记乙金额7.77`；本次不得新增账单，也不能出现自动记账通知。
9. **「向您支付」真机回归**：保持「向您支付进账」开启，发送完整原文 `【天津新元信息技术有限公司】钟元兴先生/女士，天津新元信息技术有限公司向您支付了深圳市起点云电子商务有限公司项目服务费19.40元，我司将按国家规定进行个人所得税代扣申报。您在次月底可在“个人所得税”App查询，详询4000051667`；应新增 19.40 元 `income` 账单，分类为收入侧的「其他」，且不会被记成「消费」。

## 判定口径

- 第 7、8 项验证 `RuleEngine.invalidate()` 与下一次解析的热更新，不靠重启、不靠重新授予权限。
- 开关热更新使用**自定义规则**验收。关闭系统规则后仍会回退到 `NotificationRules` 内置解析，这是现有兜底设计，不能用来判断动态规则开关是否失效。
- 第 9 项同时覆盖两条路径：系统规则「向您支付进账」优先命中；即使该动态规则被关闭或加载失败，内置 `INWARD_WORDS` 仍会把「向您支付」判为收入。

## 自动化已覆盖

- `ParsePipelineTest`：完整 19.40 元样本、内置规则强制 `income`、106 通道、动态规则命中、内置兜底，以及「给您打款」强进账。
- `RuleEngineTest`：坏 JSON 单条隔离、危险正则拒绝、规则优先级与缓存失效。
- `RuleSafetyTest`：常见灾难性回溯、超长正则与重复次数上限。

## 清理

验收结束后删除「验收-通道开关」及测试期间创建的临时账单，避免污染正式账本。
