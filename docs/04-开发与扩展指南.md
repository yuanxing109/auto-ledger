# 04 · 开发与扩展指南

> 面向接手本项目的开发者。命令与路径均以工作区 `D:\个人项目\auto-ledger` 为准，2026-11-22 实测。

## 1. 目录约定

```
auto-ledger/
├─ app/src/main/java/com/eta/autoledger/
│  ├─ AppPrefs.kt                 # 全局设置（SharedPreferences + mutableStateOf）
│  ├─ MainActivity.kt             # 唯一 Activity 入口，负责排班与权限请求
│  ├─ data/                       # 数据层：Room 实体/DAO/仓库/导入导出/规则库/备份
│  ├─ service/                    # 常驻与后台服务：通知监听/短信/健康/备份/周期 Worker/通知出口
│  ├─ screenshot/                 # 截屏记账全链路（无障碍/MediaProjection/Root + AI）
│  ├─ reminder/                   # 每日/周/月提醒（AlarmManager + Boot 重排）
│  ├─ notification/               # 超级岛/灵动岛/实况窗统一出口
│  ├─ widget/                     # 桌面小部件（2×2 / 4×2）
│  ├─ tile/                       # 快捷设置磁贴
│  ├─ settings/                   # 设置页（SettingsScreen 存根 + pages/ 子页 + SettingsUi 组件）
│  ├─ ui/                         # 组合 UI：AppRoot/LedgerApp/屏幕/组件/主题/模型
│  │  ├─ screen/                  # Home / Add / Search / Report 四大页
│  │  ├─ theme/                   # LedgerPalette（色源）/LedgerMiuixColors/LedgerTextStyles/LedgerDimens
│  │  ├─ components/ model/ window/
│  ├─ viewmodel/                  # HomeViewModel（分页）
│  ├─ util/                       # SystemAccess（权限探测与自愈）
│  └─ xposed/                     # LSPosed 模块骨架
├─ app/src/main/res/              # layout/widget_*/ values/{colors,strings,themes,accessibility_strings}
├─ tools/                         # check-ui-consistency.sh / check-kotlin-syntax.py
├─ docs/                          # 本文档集
└─ .github/workflows/android.yml  # CI
```

**命名/分层硬约定**（UI 门禁会查，见 [08](08-A方案-Miuix单源与图表迁移.md)）：
- 唯一主题根是 `AppTheme`（`ui/theme/AppTheme.kt`），任何页面禁止再包 `MiuixTheme`/`MaterialTheme`。
- 色值只能来自 `MiuixTheme.colorScheme.*` 或 `LedgerTheme.*`/`LedgerPalette`；**禁止 `Color(0x…)` 与 `Color.White` 等具名色**（`ui/theme/` 等白名单除外）。
- 字号/字重只能走 `MiuixTheme.textStyles.*`；禁止直接 `fontSize = 13.sp`、`fontWeight = FontWeight.Bold`（`ui/theme/` 除外）。
- 圆角只允许 `4/8/12/16/24/32/50.dp` 阶梯；禁止 `Toast.makeText`，统一用 `LocalSnackbar`/`LedgerSnackbar`。

## 2. 构建与运行

环境：JDK 17（CI 用 Temurin 21，AGP 9.2.0 允许）、Android SDK Platform 37 + Build-Tools 37.0.0。仓库已自带 Gradle Wrapper 9.4.1。

```bash
# 本地调试包（usesCleartext=true）
./gradlew :app:assembleDebug

# 发布包（minify + shrinkResources + usesCleartext=false）
# 需在根目录放 keystore.properties，否则回退 debug 签名
./gradlew :app:assembleRelease

# CI 同款本地覆盖（可选，避免命令行属性值中的点号触发 Gradle 任务解析）
AUTO_LEDGER_VERSION_CODE=46 AUTO_LEDGER_VERSION_NAME=0.5.40 ./gradlew :app:assembleRelease

# UI 一致性门禁（CI 必跑；退出码 1 = 有 error 级违规）
bash tools/check-ui-consistency.sh

# Kotlin 语法自检（可选，CI 未接入）
python3 tools/check-kotlin-syntax.py

# 安装
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

`keystore.properties` 需含 `storeFile` / `storePassword` / `keyAlias` / `keyPassword`；缺失时 release 走 debug 签名（可安装但不宜发布）。

GitHub Actions 在 `main` 分支推送后自动按运行号生成版本，并把唯一可直接安装的 release APK 上传到 GitHub Releases。Release 资产是 `.apk` 本体，不是 Actions artifact 下载时常见的 ZIP。

**关键依赖版本**（`app/build.gradle.kts` 实测）：miuix-ui / miuix-icons / miuix-preference 均 `0.9.5-beta03`；activity-compose `1.13.0`；lifecycle-runtime/viewmodel-compose `2.11.1`；room `2.8.5`；work-runtime-ktx `2.12.0`；`compileOnly io.github.libxposed:api:102.0.0`。**无任何第三方图表库**（报表为自绘 Canvas）。

## 3. 六组改造配方

### 配方 A · 新增一个布尔设置项
1. `AppPrefs.kt`：加 `private var fooState by mutableStateOf(prefs.getBoolean("foo", false))` 与公开 `var foo` getter/setter（setter 里 `prefs.edit().putBoolean("foo", v).apply()`）。
2. 设置页对应 `XxxPage` 用 `SwitchRow(prefs.foo) { prefs.foo = it }`。
3. 消费方（服务/仓库）读 `AppPrefs.get(context).foo`；服务内注意与界面共用同一实例。

### 配方 B · 新增一个设置子页
1. `SettingsScreen.kt` 的 `enum SettingsPage` 加一项并指定 `parent`。
2. `when (page)` 分发到新 `@Composable` 页面（建议放 `settings/pages/`，复用 `SettingsPageColumn`/`SettingsCard`）。
3. 一级入口在 `MainPage` 对应分组加 `ArrowPreference`。

### 配方 C · 新增一个自动记账渠道（如某银行 App）
1. `data/NotificationRules.kt`：在对应 `*_PKGS` 集合加包名；若为新渠道类别，扩展 `NotifyChannel` 与 `channelOf`。
2. 若通知文案特殊（金额/收支措辞不同），在分类关键词表或金额正则里补规则；分类名必须与 `CategoryStore` 对齐。
3. `AppPrefs` 若需独立开关，按配方 A 加。
4. 用真机通知复现，确认 `externalId` 稳定（同一笔重复投递不双写）；必要时调 `ParseDedup`/`merged` 窗口。

### 配方 D · 新增一种报表图表
1. 在 `ReportRepository` 追加对应聚合（如新增"标签维度"），复用 `observeBuckets`/`observeCategories` 或新增 DAO 查询。
2. 在 `ReportScreen.kt` 新增 `@Composable`，用 `Canvas` 自绘（项目不引图表库）；颜色取 `LedgerTheme` 图表色，尺寸用 `LocalDimens`。
3. 遵循门禁：不得硬编码 `Color(0x…)`、字号、非阶梯圆角。

### 配方 E · 数据库加字段（需迁移）
1. `LedgerEntity.kt` 加 `@ColumnInfo(...)` 字段。
2. `LedgerDatabase.kt` `version` +1，`addMigrations(MIGRATION_N_N+1)`，迁移用 `ALTER TABLE Bill ADD COLUMN ...`（老数据回填用 `DEFAULT`，不要回填 NULL 到 NOT NULL 列）。
3. 更新 `BackupCodec`（导出/恢复字段）与 `CsvImporter`/`XlsxExporter` 表头映射。
4. 重点：`exportSchema=false`，**没有 schema 校验兜底**，迁移 SQL 必须自己保证正确；改完务必用旧版本库文件实测升级。

### 配方 F · 新增导出格式或备份后端
- 导出：仿 `XlsxExporter` 手写目标格式（无 POI 依赖的思路），入口在 `settings/pages/ExportPage.kt`，分享走 `FileProvider`。
- 备份：仿 `WebDavClient` + `BackupRunner`，实现"建目录/上传/下载/列目录"四件事即可，序列化复用 `BackupCodec`。

## 5. 路线图（按性价比排序）

1. **补 `NotificationRules` 单测**：把「金额提取/收支判定/分类猜测」输入输出固化为 JVM 测试，是本项目最高杠杆的稳定性投入。
2. **AI Key 加固**：迁 `EncryptedSharedPreferences` 或系统 Keystore；至少避免明文。
3. **修正 `AboutPage` 许可文案**（去掉 Vico）——一行改动，先做。
4. **图表迁移（可选）**：若要彻底摆脱手绘 Canvas，按 [08](08-A方案-Miuix单源与图表迁移.md) 的取舍重新评估，务必先落地依赖与门禁，再改 ReportScreen。
5. **Xposed 模块完善**：把 `ensureGrants` 的逻辑下沉为 system_server 侧自动改写，降低用户手动授权门槛。
6. **导出 schema**：`exportSchema=true` + 目录固化，为后续迁移加编译期护栏。
