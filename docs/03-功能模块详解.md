## 5. 截屏记账 · `screenshot/*`（6 个文件）

| 文件 | 行 | 职责 |
| --- | --- | --- |
| `ScreenshotAccessibilityService.kt` | 68 | 无障碍截图（Android 11+`takeScreenshot()`，免 Root） |
| `ScreenshotCaptureService.kt` | 284 | 前台服务，编排两条抓帧路径 + 识图 |
| `ScreenshotRequestActivity.kt` | 63 | 透明授权中转（MediaProjection） |
| `ConfirmEntryReceiver.kt` | 112 | 结果通知「记一笔 / 忽略」 |
| `RootScreenshot.kt` | 39 | Root 路径 `su -c screencap -p` |
| `VisionHelper.kt` | 222 | 调 AI 模型 + 发结果通知 |

**三条抓帧路径（按优先级/可用性切换）**：

1. **无障碍（免 Root，Android 11+）**：磁贴/入口 → `ACTION_CAPTURE_ROOT` → `ScreenshotAccessibilityService.capture()`。内部 `if (SDK < R) return null`（低版本只能走其他路径）；`withTimeoutOrNull(8_000L)` 兜底，防系统回调永不返回把前台服务挂死；成功 `Bitmap.wrapHardwareBuffer().copy(ARGB_8888)` 后 `recycle` + `buffer.close()`。配置 `accessibility_screenshot_config.xml`：`accessibilityEventTypes="typeWindowsChanged"`、`canRetrieveWindowContent="false"`、`canTakeScreenshot="true"`、`notificationTimeout="100"`。
2. **MediaProjection**（Android 11 以下 / 无障碍不可用时）：`ScreenshotRequestActivity` 拿授权 → `ACTION_CAPTURE` → `ScreenshotCaptureService` 用 `ImageReader(RGBA_8888,2)` + `VirtualDisplay` 抓一帧，`latch.await(4, SECONDS)` 超时判"截屏失败，请手动上传（金融类 App 可能禁止截屏）"，再释放 virtualDisplay/reader/projection。
3. **Root**：`RootScreenshot.capture()` 直接 `ProcessBuilder("su","-c","screencap -p <cache>/root_shot.png")`，`waitFor(6s)`；`hasRoot()` 用 `su -c id -u` 是否输出 `0` 判定。

**ScreenshotCaptureService 关键约束**：
- `onStartCommand` 第一步就检查 `AppPrefs.screenshotEnabled`，关了就 `stopSelf()`（注释：旧版主链路不看开关，关了照样记账，已修）。
- 通知渠道：`screenshot_progress`（LOW）/`screenshot_result`（HIGH）；进度 id `9001`、结果 id `9002`；`ACTION_CAPTURE` / `ACTION_CAPTURE_ROOT`；`EXTRA_RESULT_CODE` / `EXTRA_DATA`。
- 前台类型：root/无障碍路径 `FOREGROUND_SERVICE_TYPE_DATA_SYNC`，MP 路径 `FOREGROUND_SERVICE_TYPE_MEDIA_PROJECTION`。
- 处理：`processBitmap` → PNG(85) → `Base64.NO_WRAP` → 未配 AI 则 `finishWithResult(null,"截屏成功，但还没有配置 AI 模型")` → 否则 `VisionHelper.callVisionModel` → `finishWithResult(parsed,null)`；异常 `"AI 解析失败：…"`。

**结果闭环**：`VisionHelper.postResult` 发带「记一笔 / 忽略」的结果通知 → `ConfirmEntryReceiver`（`ACTION_CONFIRM` / `ACTION_CANCEL`）：确认则 `LedgerRepository.add`（`source="截屏记账"`）→ 发「已入账」通知（固定 id `CONFIRMED_ID = RESULT_ID+1 = 9003`，带「撤销」）；撤销走 `UndoBillReceiver` 按 `entry_id`（自增主键，截图账无 externalId）删除。

**磁贴**：`tile/ScreenshotTileService.kt` — `needsSetup = !screenshotEnabled || aiBaseUrl 空 || aiModel 空`；已配置则延迟 1 秒抓帧（等控制中心面板收起，避免截到面板本身）。

## 6. AI 识图 · `screenshot/VisionHelper.kt`（222）

- `readImageBase64(uri/bitmap)`；`callVisionModel(prefs, base64)` 走 OpenAI 兼容 `chat/completions`（`messages` 内含 `image_url: data:image/png;base64,…`，`prompt = prefs.aiPrompt`）；`postResult(context, entry, error)` 发结果通知。

## 7. 通知监听记账 · `service/LedgerNotificationListener.kt`（247）

- `onNotificationPosted`（主线程）→ `handle`：过滤自身包名 / `FLAG_ONGOING_EVENT` / 未知渠道 → 按渠道查开关（支付宝/微信/短信/其他，未知渠道直接丢）→ 投 IO 协程 `LedgerRepository.addAutoParsed` 入库 → 成功且未开「不提示」发可撤销通知（`BillNotifier.notifyAdded`），并更新 `prefs.lastNotifyAt`。
- **折叠通知补全**：收到 `FLAG_GROUP_SUMMARY` 时，`collectGroupChildren(sbn)` 用公开的 `Notification.getGroup()` + `activeNotifications` 把同组仍在通知栏的子通知捞出来逐个 `handleOne`（注释：摘要常只剩"你有 2 笔新消息"，金额在子通知上）；捞不到就 `return`。
- **三道去重闸门**：
  1. `seen`：`LinkedHashMap(64,0.75f,true)` access-order，`MAX_SEEN=200`，键 = `NotificationRules.dedupeKey(raw)`，拦同一条通知重复回调。
  2. `merged`：`HashMap<String,Long>`，**10 秒窗口**（`MERGE_WINDOW_MS = 10_000L`）内「渠道 + 方向 + 金额 + note 前 12 字」相同只入一次（注释：摘要补全与系统逐条回调可能各送一次同一笔；必须带 note，否则同渠道 1 分钟内连点两笔同额外卖会被吞）。
  3. 跨渠道：入库前 `LedgerRepository.isRecentDuplicate(context, amount, type, source, timeMillis)`，拦"短信通道刚记为同一笔扣费"。
- `isEnabled(context)` 读 `enabled_notification_listeners` 是否含本组件；`openSettings` 跳系统通知使用权页。

## 9. 周期记账 · `service/RecurringWorker.kt`（166）+ `data/RecurringRule.kt`（91）

- WorkManager 每日跑：`schedule()` 用 `PeriodicWorkRequestBuilder(1, DAYS)` + `delayUntilNextRun()`（下一个 **00:05**，避开零点系统高峰），`ExistingPeriodicWorkPolicy.KEEP`；`runNow()` 在 App 启动时补跑一次。
- `doWork`：取今天 `[00:00, 次日00:00)` 区间 → `dao.recurringTemplates()`（is_recurring=1）→ 逐条 `RecurringRule.parse().matches(today)` → 命中则 `template.copy(id=0, source="recurring", externalId="rec_${template.id}_$ymd", isRecurring=false, recurringRule=null)` → `dao.insertAll`（**IGNORE**，`rowId=-1` 即当天已生成，幂等靠 `external_id` 唯一索引）。
- 取舍（源码注释）：用「区间内是否已生成」判幂等而非加 `lastRunDate` 字段；生成失败 `Result.success()` 跳过不重试（晚一天可接受，卡重试队列反复写库更糟）。
- `RecurringRule`：`sealed class`，`Weekly(dow)` `raw="WEEKLY_$dow"`、`Monthly(day1..28)` `"MONTHLY_$d"`、`Yearly(m,d)` `"YEARLY_$m-$d"`；`parse(raw)` 无法识别返回 null。存字符串不存 JSON（人可直读），不做节假日跳过 / 末日顺延。

## 12. 导入 · `data/CsvImporter.kt`（267）+ `data/XlsxImporter.kt`（93）

**CSV**：
- 表头识别：某行同时含"金额" + "时间/日期" + "收/支|收支|交易类型"；`detectDelimiter` 比较 `\t` 与 `,` 出现次数；`isWechat = header 含"交易单号"|"交易类型"`。
- 列索引按关键字匹配（交易时间/金额/收/支/交易类型/交易对方/商品/备注/交易单号/记账分类/子类）；跳过"中性"/"不计收支"行与 `amount<=0` 行。
- `normalizeTime`：Excel 序列号落在 `20000..80000` 时以 `1899-12-30` 为基准 `base += (serial*86_400_000.0).toLong()`（必须 `Long`，46345 天×86400 秒超 `Int`）；`isPlausibleTime` 限年份 2000..2100。
- `parseFileRange`：正则 `起始时间：\[(\d{4}-\d{2}-\d{2})` / 终止时间；`extractOrderDateTime`：`(20\d{2})(0[1-9]|1[0-2])(0[1-9]|[12]\d|3[01])(\d{2})(\d{2})(\d{2})` 从交易单号还原时间；无文件范围时接受 2020-01-01..2030-12-31（避免再出现 206x/207x）。
- `wechatCategory`：商户消费/扫二维码/二维码→消费；转账/群收款→转账；红包→红包；退款→退款；否则 `detectCategory`。微信 note = 交易对方·商品·备注 distinct 后 `take(120)`；`externalId = "wx:$order"`；`source` = "微信导入" / "CSV 导入"。
- 无表头时退化为逐行正则（`dateRegex` 抹日期后取首个金额）。
- 导出 `export(entries)`：表头 `id,type,category,amount,time,note,source`，金额 `%.2f`，`esca` 双引号包裹并双写内部引号。
- 最终都走 `LedgerRepository.addImported`。

**XLSX 导入**：纯 regex 解析 zip —— `xl/sharedStrings.xml`（`<si>`/`<t>`）、`xl/worksheets/sheet1.xml`（回退任意 `sheet*.xml`）逐 `<row>`/`<c>` 解析，`r="([A-Z]+)\d+"` 定位列（26 进制），`t="s"` 查共享表、`inlineStr` 去标签反转义；转成 CSV 委托 `CsvImporter.import`；临时文件落 `cacheDir`，`finally` 删除；任何 `Throwable` 返回 0。

## 14. WebDAV 云备份 · `data/WebDavClient.kt`（142）+ `data/BackupRunner.kt`（87）+ `data/BackupCodec.kt`（81）

- `WebDavClient`：`CONNECT_MS=15_000`、`READ_MS=60_000`；`Target(dir,user,pass)`（`normalized`）；`test(target)` = 建目录 + 写探针 + 删探针，失败抛 `IOException`。只做建目录/上传/下载/列目录，兼容坚果云、群晖、Nextcloud、TeraCloud。
- `BackupRunner`：`FILE_LATEST="autoledger-backup.json"`、`KEEP_DAILY=7`、`AUTO_INTERVAL_MS=20h`；`backup()` 传 latest + `autoledger-backup-$day.json` → prune（倒序 `drop(7)` 删）；`restore()` 下载 latest → decode → `addImported` 合并（"恢复完成：新增 N 笔，跳过 M 笔重复"）；`autoBackupIfDue` 需 `davAuto && davConfigured && 距上次≥20h`。
- `BackupCodec`：`VERSION=2`；JSON `{app:"auto-ledger", version, exportedAt, count, bills:[...]}`；decode 兼容纯数组或对象（`require(version in 1..VERSION)`）；**不直接拷 SQLite 文件**，因为换机恢复时 Room 版本可能不同会被 schema 校验拒绝，JSON 走 `addImported` 的迁移与去重。
- 调度：`service/BackupJobService.kt`（JobScheduler，`JOB_ID=4302`，周期 6 小时，实际是否上传由 `autoBackupIfDue` 的 20h 窗口决定）。

## 16. 通知出口与超级岛

- **BillNotifier**（`service/BillNotifier.kt`，110）：自动记账统一通知出口（通知监听/短信共用）。渠道 `CHANNEL_AUTO="auto_ledger_bill"`；**每笔账单用 `externalId.hashCode()` 派生独立通知 id**（注释：共用固定 id 会让多笔互相覆盖，只剩最后一笔可撤销）；带「撤销」action → `UndoBillReceiver`；`prefs.singleMuted` 时静默入库；`prefs.persistentSingle` 时 `setOngoing`；`IslandNotifier.decorate(... islandSingle)` 上岛。
- **IslandNotifier**（`notification/IslandNotifier.kt`，304）：跨厂商「超级岛/灵动岛/实况窗」统一出口，任何一步失败降级普通通知。`Vendor{XIAOMI,VIVO,OPPO,HONOR,SAMSUNG,OTHER}`，`vendor()` 按 MANUFACTURER+BRAND 判定；`supportsLiveUpdates()`=SDK≥36；`canPostPromoted`=SDK≥36 且 `canPostPromotedNotifications()`；`Spec(id,title,text,critical,channelId,channelName,ongoing,enableVendorIsland,category)`；`deliver()`：ensureChannel → `applyLiveUpdate`（`Notification.ProgressStyle`+`FLAG_PROMOTED_ONGOING`，需 `islandLiveUpdates && supportsLiveUpdates()`）→ `applyVendorExtras`（小米 `extras["miui.focus.param"]` `param_v2` JSON / vivo `notification.superx.*` Bundle）→ `plain` 降级。小米还需 `prefs.miuiBusinessId`（留空不上小米岛）。
- **UndoBillReceiver**（76）：`ACTION_UNDO`；两条链路 —— 自动记账按 `external_id` 删（`deleteByExternalId`）、截图记账按 `entry_id` 删；`NOTIFY_ID=9100` 兜底。
- **ConfirmEntryReceiver**（112）：截图记账「记一笔/忽略」，见 §5。

## 17. LSPosed 模块 · `xposed/LedgerModule.kt`（21）

`class LedgerModule : XposedModule()`（依赖 `compileOnly io.github.libxposed:api:102.0.0`），`onSystemServerStarting(param)` 里**只 `Log.i("AutoLedger","attached to system_server, classLoader=…")`**——纯骨架，尚无任何实际 hook。

- 声明文件：`app/src/main/resources/META-INF/xposed/module.prop`（`id=com.eta.autoledger`、`name=自动记账`、`version=0.2.2`、`versionCode=3`、`author=Eta`、`minApiVersion/targetApiVersion=102`）、`scope.list`=`system`、`java_init.list`=`com.eta.autoledger.xposed.LedgerModule`。
- 代码注释列出的**计划**：① 自动把本应用写入 `enabled_notification_listeners`（免手动授权）；② 覆盖安装后保持通知使用权；③ 可选 SystemUI 兜底采集。均未实现。
- ⚠️ **实现不一致**：`SystemAccess.moduleActive` 读 `Settings.Secure` 的 `autoledger_module_active`，但当前没有任何代码写这个键（模块是骨架、App 侧也不写）→ `moduleActive` 实际恒为 `false`，UI 里"模块已激活"永远显示未激活。见 [04 §4](04-开发与扩展指南.md#4-已知问题清单)。

## 18. 系统权限体检与自愈 · `util/SystemAccess.kt`（272）+ `service/HealthJobService.kt`（74）

- **SystemAccess**：`notificationListenerGranted` / `accessibilityGranted` / `smsGranted`（RECEIVE_SMS 运行时权限）/ `notificationGranted`（`NotificationManagerCompat.areNotificationsEnabled`）/ `batteryUnrestricted`（`isIgnoringBatteryOptimizations`）/ `exactAlarmAllowed`（SDK<S 直接 true，否则 `canScheduleExactAlarms`）/ `channelEnabled(context,channelId)`（importance==NONE 视为关）/ `moduleActive`（`Settings.Secure` 标志，`runCatching` 兜底 false）；跳转 `openNotificationListener` / `openAccessibility` 等。
- 常量：`CHANNEL_AUTO`、`CHANNEL_SHOT_PROGRESS`、`CHANNEL_SHOT_RESULT`、`CHANNEL_REMINDER`、`MODULE_FLAG="autoledger_module_active"`、`EXTRA_APP_UID="android.provider.extra.APP_UID"`（注释：MIUI/HyperOS 通知设置页缺它会 NPE 崩溃）。
- `ensureGrants(context)`：已授 `WRITE_SECURE_SETTINGS` 才把被 ROM 关掉的通知使用权/无障碍写回；否则什么都不做。
- **HealthJobService**：`JOB_ID=4301`、`PERIOD_MS=15min`（JobScheduler 最小周期）；只调 `ensureGrants`。用 JobScheduler 而非常驻前台服务（注释：无需常驻通知，且进程被杀后下周期能重新拉起本进程，顺带让 NotificationListenerService 重绑 = 免费复活机会）。
- 入口页：`settings/pages/SystemAccessPage.kt`（352）。
