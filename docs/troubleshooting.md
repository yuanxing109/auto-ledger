# 故障排查

## 1. 通知自动记账不工作

检查顺序：

1. 设置 -> 权限与后台 -> 通知使用权。
2. 应用通知总开关。
3. “自动记账”通知渠道。
4. 自动记账设置中的对应通道开关。
5. 是否命中全局忽略词。
6. 日志中是否出现 `AutoLedger` 解析错误。

通知使用权被 ROM 关闭时，设置页会显示警告。授予 `WRITE_SECURE_SETTINGS` 后可使用“一键修复”，否则需要手动重新开启。

## 2. 短信不记账

检查：

- `RECEIVE_SMS` 权限。
- 发送方是否通过金融来源闸门。
- 正文是否包含可识别金额与方向。
- 是否命中全局忽略词。
- 是否被视为营销或非交易短信。
- Logcat 是否出现短信解析失败。

平板或没有电话硬件的设备可安装应用，但不会收到短信广播。

## 3. 同一笔消费被记录两次

可能原因：

- 两条来源超过 5 分钟。
- 同源记录超过 1 分钟。
- 金额换算后不完全相同。
- 来源标签缺失微信/支付宝或银行语义。
- 已有记录被标记为内部转账。
- 真实两笔同额消费被系统视为独立交易。

查看两条记录的来源、时间和 `isTransfer` 状态。不要只修改金额，保留时间与来源便于排查。

## 4. 内部转账误判或漏判

自动配对要求：

- 金额分相同。
- 一笔收入、一笔支出。
- 时间差不超过 5 分钟。
- 至少一笔带“还款、转入、转出、信用卡、微信转账”等语义，或分类为“转账”。
- 不含退款、撤销、冲正、失败、关闭。
- 可识别卡号尾号相同时不配对。

误判时在账单编辑弹窗中解除合并。之后两条记录会重新进入普通统计。

## 5. AI 测试连接成功但识图失败

测试连接只发送短文本 `ping`。识图还可能因图片格式、MIME、模型视觉能力或返回长度失败。

检查：

1. Model Name 是否支持图片输入。
2. Base URL 是否为兼容 `/v1/chat/completions` 的地址。
3. 图片是否可正常打开。
4. 日志中是否有 `AI_ERROR`。
5. 模型是否返回空正文。
6. 单图交易过多时是否达到 `max_tokens=1200`。

界面只显示稳定错误文案。完整模型原文应在 Logcat 的 `AI_ERROR` 中查看。

## 6. AI 返回格式错误

客户端已经支持：

- Markdown 代码块。
- 前置解释。
- JSON 对象。
- JSON 数组。
- `transactions` 包装。
- 多个代码块，优先最终块。

仍然失败时检查模型是否：

- 输出截断 JSON。
- 输出多段互不闭合的示例。
- 返回空内容。
- 返回图片不可读的错误页面。

可先切换为非思考型模型或使用支持的视觉模型验证。

## 7. 截图记账失败

### 无障碍路径

- Android 11+。
- 设置中已开启无障碍截图服务。
- 截屏记账总开关已开启。
- AI Base URL 与 Model Name 已配置。

### MediaProjection 路径

- 需要在系统弹窗中允许录屏。
- Android 14+ 需要对应前台服务类型。
- 页面禁止截图时会失败。

### 数据保护页面

银行或支付安全页面可能返回黑屏或禁止捕获。此时使用相册上传。

## 8. 确认入账通知没有出现

- 通知总开关。
- “识图记账”通知渠道。
- Android 13+ 通知权限。
- 识别结果是否为空。
- 是否出现格式错误。

结果通知使用固定 ID。新的识别会覆盖尚未确认的旧结果。

## 9. WebDAV 备份失败

检查：

- 地址是否以可访问的 WebDAV 目录结尾。
- 用户名和密码是否为应用专用密码。
- release 连接是否使用 HTTPS。
- 服务端是否允许 `PUT`、`PROPFIND`、`MKCOL` 和 `DELETE`。
- 云端目录是否可写。

备份文件名：

- `autoledger-backup.json`
- `autoledger-backup-yyyyMMdd.json`

自动备份最短间隔为 20 小时，保留最近 7 份日备。

## 10. 报表金额与列表笔数不一致

这是预期口径：

- 列表保留内部转账。
- 金额统计排除内部转账。
- 金额统计排除周期模板。

如果报表仍异常，检查对应账单的 `is_recurring` 与 `is_transfer`。

## 11. 周期账单重复

周期实账唯一键必须由 `RecurringExternalIds.generate()` 生成。若同一模板同一天出现两笔，检查：

- `external_id` 是否一致。
- 手动保存和 Worker 是否都调用统一生成函数。
- 数据库唯一索引是否完整。

## 12. 构建失败

### SDK 或 JDK

确认 JDK 21、SDK 37.2 和 Build Tools 37.0.0。

### 签名

检查 `keystore.properties` 中四个字段均存在。本地无签名文件时会回退 debug 签名，CI Release 发布前必须确认实际签名。

### UI 门禁

```bash
bash tools/check-ui-consistency.sh
```

R1 至 R3 会阻断。R4 至 R7 当前是警告。

### 单元测试

```powershell
.\gradlew.bat :app:testDebugUnitTest --stacktrace
```

报告位于 `app/build/reports/tests/testDebugUnitTest/index.html`。

## 13. CI 没有发布新 APK

- 确认变更已推送到 `main`。
- 查看 Actions 是否被新的同分支运行取消。
- 检查 UI 门禁、测试和构建步骤。
- 检查 GitHub Release 是否已有同 Tag `v1.0.0`。
- 检查 Workflow 的 `contents: write` 权限。

## 14. 收集日志

只读调试准备：

1. 手机开启 USB 调试。
2. 电脑执行 `adb devices`，确认设备状态为 `device`。
3. 复现问题。
4. 收集：

```bash
adb logcat -d -s AutoLedger AI_ERROR AndroidRuntime
```

共享日志前检查是否包含账单文本、账号、路径或其他隐私信息。
