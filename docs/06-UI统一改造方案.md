# 06 · 全局 UI 统一改造方案

> 目标：把「深色模式半成品 + 各页各写一套颜色」收敛成**一套 token、两套主题、一份组件规范**，并重做搜索页。
> 技术栈（已确认）：Kotlin / JDK 17 · Jetpack Compose（**无 material3**）· Miuix `top.yukonga.miuix.kmp` 0.9.5-beta01 · Room 2.8.5。
> 主题入口：`app/src/main/java/com/eta/autoledger/ui/LedgerTheme.kt`（9 个语义色）+ `ui/LedgerApp.kt` 的 `ThemeController`。

---

## 0. 结论摘要

1. **深色模式的病根不是"没做"，而是"做了一半"**：`LedgerTheme` 已经在首页/添加/报表/设置大部分区域生效，但仍有 **6 个文件、约 120 处 `Color(0x…)` 硬编码**绕过它——报表页顶栏纯白、AI 识图弹层白底、记账键盘区、首页蓝色渐变卡、分类马卡龙色板。
2. **风格不统一来自"每页自己定数"**：圆角有 8/12/16/18/22/24dp 六种，字号有 11/12/13/14/15/17/26/34sp 八种混用，金额格式有 `+57.00` / `-¥39.90` / `¥ 0.00` / `2,012.53` 四种写法。
3. **配色需要重做**（不是微调）：现浅色 `#F2F7FF` 偏"医疗蓝"，深色 `#0D1117` 又过于 GitHub 化，两套之间没有共享的语义角色。
4. 需求 4 的两处改动很小但正确性明确：负数对比值 → `danger` 红；记账金额 → `FontWeight.Bold`。
5. 搜索页（图 9）的问题是**信息架构**，不是配色：筛选条件和搜索框抢空间、结果不分日期组、300 条截断无提示。

### 2.3 间距与圆角

- 间距：`4 / 8 / 12 / 16 / 20 / 24`（4 的倍数）；页面左右 padding 16dp、卡片内 padding 16dp、卡片间距 12dp。
- 圆角：`8dp`（chip、小按钮）/ `12dp`（输入框、按钮）/ `16dp`（卡片、列表项、结果卡）/ `24dp`（底部 sheet 顶角、大卡片）。

## 4. 图 9 · 搜索页重新设计

### 4.1 现方案的问题

1. 搜索框和返回箭头挤在同一行，输入区只剩 ~60% 宽度，长关键字看不全。
2. 两组 chip 常驻占掉 100dp 高度，其中「类型行」还混进了「最低 — 最高」金额输入 —— **筛选器、输入框、结果区三者视觉同级**，用户不知道从哪下手。
3. 结果不分日期组，与首页「按日分组 + 日汇总」的心智模型断裂。
4. 「共 300 笔」是 SQL `LIMIT 300` 的截断值，被当成真实总数展示，**且无任何提示**。
5. 金额色语义混乱：`+¥57.00` 绿（收入，对）、`-¥39.90` 白（支出，对），但「转账 +57.00」也用绿 —— 转账不属于收入。
6. 无排序、无「清除筛选」可见入口、无空状态。

### 4.3 分区与交互

| 区 | 内容 | 交互 |
| --- | --- | --- |
| ① 顶栏 | 仅「←」返回 | 48dp 触控；`BackHandler` 已接 |
| ② 搜索框 | 全宽、`surfaceVariant` 底、放大镜图标、右侧「✕」清除（有内容时出现） | 输入 300ms 防抖后查询（现在每次按键即查，会产生大量 Flow 重建） |
| ③ 条件栏 | 默认只显示「⚙ 筛选」按钮；**有任何筛选时**才展开对应 chip，每个 chip 带「✕」单删 | 点「⚙ 筛选」→ BottomSheet（见 4.4） |

## 5. 需求 4 的两处具体改法

### 5.1「比上月少」改红色

报表 `OverviewCard` 里现在是：

```kotlin
// 现状（ui/screen/ReportScreen.kt，概览卡「比上月」一栏）
val diff = aggregate.total - aggregate.previousTotal
Text(
    text = (if (diff >= 0) "+" else "-") + money(abs(diff)),
    color = LedgerTheme.accent,   // ← 统一用蓝色，正负不分
)
```

改为：

```kotlin
val diff = aggregate.total - aggregate.previousTotal
Text(
    text = (if (diff >= 0) "+" else "-") + money(abs(diff)),
    color = if (diff < 0) LedgerTheme.danger else LedgerTheme.textSecondary,
    // 负数（比上月少）用红色；正数保持中性灰，避免"涨了就红"的歧义
)
```

> 若产品语义是「支出增加=不好」，把条件反过来即可；建议把这条规则做成 `OverviewCard` 的参数 `negativeIsGood: Boolean`，报表页按 tab（支出/收入）传不同值。

### 5.2 记账金额加粗

记一笔金额区（`ui/screen/AddScreen.kt` 金额卡）现在是常规字重、颜色偏浅：

```kotlin
Text(text = "¥ ${amountText}", fontSize = 34.sp, fontWeight = FontWeight.Normal, color = ...)
```

改为：

```kotlin
Text(
    text = "¥ ${amountText}",
    fontSize = 34.sp,
    fontWeight = FontWeight.Bold,          // ← 加粗
    color = if (amountText == "0.00") LedgerTheme.textTertiary else LedgerTheme.text,
    fontFeatureSettings = "tnum",
)
```

同时首页条目金额、搜索结果金额一并改 `SemiBold`（见 §2.5），保持"钱的数字都更重"的一致印象。
