# 03 · 功能模块详解

## 1. 手动记账（`ui/screen/AddScreen.kt`，807 行）

**状态**：金额输入串 `amountInput`（字符串，`toDoubleOrNull` 兜底 0）、`type`（0=支出/1=收入/2=其他）、`selectedCategory`、`calendar`（Calendar，日期+时间）、`note`、`showPicker`。

**关键实现**

| 能力 | 做法 |
| --- | --- |
| 三段式 | `type` 0/1/2 → `"expense"/"income"/"other"`（`AddScreen.kt:197-201`） |
| 分类网格 | `categoriesFor(context, type)`（`:118`）读 `CategoryStore`，随 type 切换 21/8/4 类 |
| 日历 | 自绘月历 + 时间选择弹层（`showPicker`），时间文案：同日显示"今天 HH:mm"，跨日显示"MM月dd日 HH:mm"（`:185-187`） |
| 金额键盘 | 自定义数字键盘（不用系统输入法），支持负数标记 `negative` |
| 保存 | `save(reset)`（`:191-219`）→ 校验 `raw > 0` → `LedgerRepository.add(context, LedgerEntry(...))` |

**保存时的字段映射**

```kotlin
id = 0L                              // 交给 SQLite 自增，Room 对 0 视为 autoGenerate
amount = raw
type = "expense" | "income" | "other"
category = selectedCategory
time = SimpleDateFormat("yyyy-MM-dd HH:mm", Locale.CHINA).format(calendar.time)
note = note
source = "手动记账"
```

> ✅ **已修复**：主键改为 `@PrimaryKey(autoGenerate = true) val id: Long = 0L`（`data/LedgerEntity.kt:12-16`）；`insertAll` 换成 `OnConflictStrategy.IGNORE` 并返回 `List<Long>`（被忽略的位置为 `-1`），导入去重靠 `external_id` 唯一索引而不是「覆盖」。同毫秒连记两笔现在是两条不同记录。

保存成功后：弹 Toast "已记录 xx ¥N"，清空金额/备注/负号；`reset=false` 时回调 `onDone()` 切回首页。

## 2. 首页（`ui/screen/HomeScreen.kt` 648 行 + `viewmodel/HomeViewModel.kt` 140 行）

**结构**：汇总卡（今日/本月支出、本月收入）→ 预算卡（`prefs.homeBudgetCard` 为 true 时，`HomeScreen.kt:146-148`）→ 按日分组的账单列表。

**分页与防抖**（`HomeViewModel`）
- `pageSize = 20`；首屏 `firstPage = observePaging(context, pageSize, 0)`（Flow，Room 变更自动推送）；后续页累积在 `extraPages: MutableStateFlow<List<LedgerEntry>>`，`billsFlow = combine(firstPage, extraPages) { first, extra -> (first + extra).filter { seen.add(it.id) } }` —— 新插入的账单会同时出现在首屏 Flow 和 extra 里，用 `seen`（按 `id`）去重，否则列表出现重复行。
- **游标分页**：`loadNextPage()` 取列表最后一条的 `(timeMillis, id)` 作游标调 `LedgerDao.pageBefore(cursorTime, cursorId, pageSize)`，SQL 为 `WHERE timestamp < :t OR (timestamp = :t AND id < :id) ORDER BY timestamp DESC, id DESC LIMIT :limit`。固定 20 行一趟，翻到第 10 页也只读 20 行，不再像旧的 `limit = pageSize * pages` 那样每次重扫 0..N。
- `hasMore = !reachedEnd && bills.size < totalCount`；某次返回不足 20 条即 `exhausted = true`。`observeCount` 数字变化（新增/删除）时清空 `extraPages` 并复位 `exhausted`，回到只有首屏的状态。
- 触底：`loadMoreRequests`（`MutableSharedFlow(extraBufferCapacity=1)`）+ `debounce(300)`，300ms 内只处理最后一次，并有 `loading` 互斥。
- `LaunchedEffect(listState, bills.size, hasMore)`（`HomeScreen.kt:123`）监听滚动触发 `loadMore()`。
- `init` 里 `Dispatchers.IO` 跑 `LedgerRepository.repairTimestamps(context)`（`:67-70`），修 `timestamp=0` 的历史数据。

**交互**
- 长按账单行 → `combinedClickable(onClick = {}, onLongClick = ...)`（`HomeScreen.kt:500-504`）→ 打开编辑（`editingEntry`）或删除确认。
- 行内时间展示：优先 `entry.timeMillis`，否则 `LedgerRepository.parseTime(entry.time)` 回退（`:549`），并拼 `weekday(cal)`（`:564`）。

### 2.1 搜索与筛选（`ui/screen/SearchScreen.kt`，370 行）

- 入口：首页「最近账目」标题行右侧的「搜索」。
- 单一 SQL 组合筛选 `LedgerDao.search(minAmount, maxAmount, start, end, type, category, keyword, limit)`：`amount BETWEEN` + `timestamp >= :start AND < :end` + `:type = '' OR type = :type` + `:category = '' OR category = :category` + `:keyword = '' OR note LIKE '%'||:keyword||'%' OR category LIKE … OR source LIKE …`，`ORDER BY timestamp DESC, id DESC LIMIT :limit`。
- UI：时间 chips（全部 / 本月 / 上月 / 近三月 / 今年）、类型 chips（全部 / 支出 / 收入 / 其他）、选中类型后出现分类 chips（`CategoryStore.names`）、两个金额输入框；结果区显示「共 N 笔」+ 收支合计。
- 边界：`limit` 硬上限 300，不做无限滚动；关键字只搜 `note / category / source`，不含金额。

## 3. 报表（`ui/screen/ReportScreen.kt` 1023 行 + `data/ReportRepository.kt` 123 行）

**维度**：`tab ∈ {0 周, 1 月, 2 年}` × `income ∈ {支出, 收入}` × `offset`（0 本期，负数向前翻）。

**四块图**

| 区块 | 实现要点 |
| --- | --- |
| 概览卡 | 本期支出、日均、环比（`total vs previousTotal`）、结余 |
| 折线趋势 | 点按/左右拖动时气泡跟手，**竖向引导线**对齐当前刻度 |
| 柱状对比 | 本期 vs 上期，选中柱高亮 + 气泡 |
| 环形构成 | 马卡龙配色（`CategoryStore.palette`）、细白间隙、折线引线、标签自动避让、环心合计 |
| 分类排行 | 笔数、占比、金额、进度条，按 `total DESC` |

**数据来源**：`ReportRepository.observe(context, tab, offset, income)` 返回 `ReportAggregate`，一次取齐 `trend`（折线桶）、`bars`（对比桶）、`categories`（环形/排行）、`total/previousTotal/expense/income`。

**周起点**：周一。`startOfWeek` 用 `MONDAY - dayOfWeek` 计算，周日（`DAY_OF_WEEK=1`）回绕到上周一，需要 `+7` 校正。

## 4. 截屏记账（`screenshot/` 6 个文件）

### 4.1 三条取图路径

| 路径 | 触发 | 前置条件 | 代码 |
| --- | --- | --- | --- |
| 无障碍 | 磁贴 / `ACTION_CAPTURE_ROOT` | 设置 → 功能管理 → 无障碍截图（Android 11+，免 Root、不弹录屏授权） | `ScreenshotAccessibilityService` |
| MediaProjection | 相册/拍照入口或透明页 | 每次需用户点"开始录制"，且要 `POST_NOTIFICATIONS` | `ScreenshotRequestActivity` → `ScreenshotCaptureService` |
| Root | 无障碍不可用时的兜底 | 设备已 root，`su` 可用 | `RootScreenshot`（`su -c screencap -p <cache>/root_shot.png`，`waitFor 6s`） |

无障碍路径的优势：`AccessibilityService.takeScreenshot()`（API 30+）无需录屏授权、无红框提示；实现上把 `HardwareBuffer` wrap 成 `Bitmap` 再 `copy(ARGB_8888)`，并通过单例 `instance` + `suspend fun take()` 暴露给服务调用。

### 4.2 MediaProjection 抓帧（`ScreenshotCaptureService`，276 行）

1. 前台服务，`START_NOT_STICKY`；Android 14+ 必须声明 `foregroundServiceType`——MediaProjection 路径用 `mediaProjection`，Root 路径用 `dataSync`（两者都在 Manifest 里注册）。
2. `VirtualDisplay` + `ImageReader`（`PixelFormat.RGBA_8888`）。
3. 取帧时处理 **rowStride padding**（`bitmapRowStride != width * 4` 时按行裁剪），否则截图会错位。
4. 用 `CountDownLatch.await(4s)` 等首帧，超时走失败分支：`"截屏失败，请手动上传（金融类 App 可能禁止截屏）"`。
5. 进度通知 `PROGRESS_ID`=`9001`："正在截屏并交给 AI 解析…"；前台结果通知 `RESULT_ID`=`9002`；AI 识图结果走检查 channel `screenshot_result`（"识图记账"）的 `notify(9003)`（`VisionHelper.kt:182`）；截图失败走 `notify(9004)`（`ScreenshotCaptureService.kt:205`，标题"截屏记账"，带"开启无障碍截图"按钮跳 `ACTION_ACCESSIBILITY_SETTINGS`）。

### 4.3 识别与确认

- `VisionHelper.callVisionModel(prefs, base64)`：`POST {aiBaseUrl}/chat/completions`，`connectTimeout 15s` / `readTimeout 60s`，`Authorization: Bearer {aiKey}`。
- 响应解析容错链：`choices[0].message.content` → 兼容 `reasoning_content` → `choice.text` → 根 `content`；去 ` ```json ` 围栏后用 `Regex("\{[\\s\\S]*\}")` 抠 JSON；失败报 `"模型没有返回 JSON"`；HTTP 非 2xx 抛 `"HTTP $code"`；内容为空提示"请确认该模型支持图片输入"。
- 结果通知：标题 `"识别到收入/支出 ±¥ %,.2f"`，正文 `分类·时间·备注`，`PendingIntent → ConfirmEntryReceiver`：
  - `ACTION_CONFIRM` → `LedgerRepository.add(source="截屏记账")` + 取消通知 + Toast "已入账"（`ConfirmEntryReceiver.kt:29`）
  - `ACTION_CANCEL` → 仅取消通知

### 4.4 磁贴（`tile/ScreenshotTileService`）

## 6. 通知监听 / 短信记账（`service/LedgerNotificationListener.kt` 229 行 + `service/SmsReceiver.kt` 100 行 + `data/NotificationRules.kt` 424 行）——已实现

两条链路共用同一套规则内核与同一个通知出口：

- 通知：`NotificationListenerService.onNotificationPosted` → 白名单/开关/系统噪声过滤 → `NotificationRules.parse` → `LedgerRepository.addImported` → 「自动记账」通知（可撤销）。
- 短信：`SMS_RECEIVED` 广播 → `SmsReceiver` → 发送方/噪声过滤 → `NotificationRules.parseSms` → 同一个 `addImported` → 同一个通知出口（`service/BillNotifier.kt`）。

### 6.1 规则库 `NotificationRules`（纯函数，无 Android 依赖，可单测）

| 步骤 | 实现 |
| --- | --- |
| 渠道识别 | `channelOf(pkg)`：支付宝 `com.eg.android.AlipayGphone`、微信 `com.tencent.mm`、13 家银行/云闪付、4 个短信应用、10 个外卖/出行/电商包名 → `ALIPAY/WECHAT/BANK/SMS/OTHER` |
| 文本拼接 | 标题 + `EXTRA_BIG_TEXT`（缺失回退 `EXTRA_TEXT`），压缩连续空白 |
| 噪声过滤 | `noiseWordsOf(channel)`：通知走 `BLOCK_WORDS`（优惠券、红包封面、账单已出、还款日、可用额度、验证码、登录、广告、余额宝、收益到账、已折叠……）；短信走 `SMS_BLOCK_WORDS`（额外拦贷款/分期/提额/逾期/退订/营销/话费/流量/套餐），但**刻意不拦「可用额度 / 剩余额度」**——真实信用卡消费短信几乎都带这句 |
| 金额抽取 | 先取 `AMOUNT_NEAR_VERB`（收支动词后 12 字内的数字，避开「可用额度 20,000.00 元」这类尾数），未命中再按 `…元/圆` → `¥/￥…` → ≤12 字裸数字降级；多候选时取文本中**最靠前**的一个，要求 `0 < amount ≤ 1,000,000` |
| 收支方向 | 退款→`income`(0.9)；信用卡还款→`other`(0.8)；提现/充值→`other`(0.7)；强收入词（收款/到账/已入账）且无「支付成功」→`income`(0.75)；否则按收入词/支出词命中数比较，平局且含「成功」+支付→`expense`(0.6) |
| 分类映射 | 按 `CategoryStore.names(type)` 的现有分类做关键词匹配，落空回退「其他」 |
| 幂等键 | `dedupeKey(raw) = pkg|title|text|bigText|postTime`；`dedupeId(raw, amount, type, prefix) = prefix + md5("$dedupeKey|$amount|$type").take(20)`，前缀 `ntf`（通知）/`sms`（短信），落到 `Bill.external_id` 唯一索引上做幂等 |

### 6.2 监听器 `LedgerNotificationListener`

- 协程：`CoroutineScope(SupervisorJob() + Dispatchers.IO)`，`onDestroy` 里 `scope.cancel()`。
- 内存去重：`LinkedHashMap(64, 0.75f, true)` 的 LRU，`removeEldestEntry` 上限 200 条，`synchronized(seen)` 读写。
- 过滤顺序：自身包名 → `FLAG_ONGOING_EVENT` → 非白名单包 → 对应渠道开关（`alipayEnabled`/`wechatEnabled`/`smsEnabled`/`otherEnabled`）→ 文本为空 → 内存去重。`FLAG_GROUP_SUMMARY` 不再直接丢弃，改走折叠补全（见 6.2.1）。
- 入库：`LedgerRepository.addImported(context, listOf(bill.toEntry(now)))`，`added > 0` 才标记已见并通知，因此重复投递与已存在单号不会重复入账。
- 入库通知（`service/BillNotifier.kt`，通知与短信共用的出口）：渠道 `auto_ledger_bill`（「自动记账」，`IMPORTANCE_DEFAULT`），标题「自动记账 支出 -¥12.50」，正文「分类 · 时间 · 备注」，`BigTextStyle`，`setOngoing(prefs.persistentSingle)`，`singleMuted` 时静默；通知 id 固定 `9100`，带「撤销」按钮 → `UndoBillReceiver` 按 `externalId` 删行并取消通知（`addImported` 是 REPLACE 插入不回填主键，所以不能用 id 撤销）。
- 授权状态：`isEnabled(context)` 读 `Settings.Secure.enabled_notification_listeners`，逐项 `ComponentName.unflattenFromString` 比对；`openSettings` 打开 `ACTION_NOTIFICATION_LISTENER_SETTINGS`。
- 异常兜底：`onNotificationPosted` 整体 `runCatching`，任何异常只记 `Log.w`，不会让系统回收监听服务。

#### 6.2.1 折叠摘要补全与内容归并

微信/支付宝把多条通知折叠成一个 group 时，摘要那条（`FLAG_GROUP_SUMMARY`）往往只剩「你有 2 笔新消息」，金额在子通知上。

- `handle()` 遇到摘要不再丢弃，而是 `collectGroupChildren(sbn)`：取 `sbn.group`（或 `notification.group`），遍历 `activeNotifications`，在同包名、同 group、不同 key 的通知里捞子通知，逐个交给 `handleOne()`。
- 子通知通常紧跟摘要到达；若摘要到达时 `activeNotifications` 里还没有同组通知，只记一条 `Log.d` 返回，等子通知自己的回调。
- 两条路径（摘要补全 / 系统逐条回调）会看到同一笔钱，用 10 秒窗口按 `渠道|方向|金额|备注前 12 字` 归并（`mergeKeyOf` / `isRecentlyMerged` / `markMerged`）。带备注是必须的：同渠道 10 秒内连点两笔同额外卖是常态，只按金额会把第二笔真账吞掉。
- 长期去重仍由 `external_id` 唯一索引兜底，窗口只负责吸收「同一条通知的重复投递」。
- 已知边界：若摘要到达时子通知已被系统移除（用户点开折叠、或系统合并后不再回调），这一笔抓不到 —— 回到非 Root 模式的上限。

### 6.3 设置入口

`settings/SettingsScreen.kt` 的「自动记账」页顶部是**通知使用权**一行（`LedgerNotificationListener.isEnabled` 读 `Settings.Secure.enabled_notification_listeners`，未授权时跳 `ACTION_NOTIFICATION_LISTENER_SETTINGS`），下方开关为支付宝 / 微信 / 短信记账 / 其他四个渠道。

短信开关是危险权限开关：`checked = prefs.smsEnabled && smsGranted`，点开时先走 `rememberLauncherForActivityResult(RequestPermission)` 申请 `RECEIVE_SMS`，被拒则 Toast 提示并把 `smsEnabled` 置回 false（`SettingsScreen.kt:277-308`，`hasSmsPermission` 在文件末尾）。

### 6.4 短信通道 `SmsReceiver`

- 广播声明：`<receiver .service.SmsReceiver android:exported="true" android:permission="android.permission.BROADCAST_SMS">` + `android.provider.Telephony.SMS_RECEIVED`，`priority=999`；权限 `RECEIVE_SMS`（`AndroidManifest.xml:10`、`:80-90`）。
- 生命周期：广播必须 10 秒内返回，所以 `goAsync()` + `CoroutineScope(SupervisorJob() + Dispatchers.IO)` + `AtomicBoolean` 保证只 `finish()` 一次，异常也走 `finally`。
- 长短信：`Telephony.Sms.Intents.getMessagesFromIntent(intent)` 的多段 PDU 按 `originatingAddress` 分组，`messageBody` 按序拼接，时间取 `max(timestampMillis)`。
- 发送方白名单 `plausibleSender(sender, body)`：`955xx` / 5-6 位短号 / 手机号直接放行；`106`、`125`、`10` 开头的通道号要求正文含金融词（银行/信用卡/尾号/人民币/余额/消费/转账/入账/扣款/交易/取现/还款），否则丢弃——挡掉电商与运营商营销短信。
- 入库与通知：与通知监听完全一致（`addImported` + `BillNotifier.notifyAdded`），重复短信、已导入过的账单不会二次入账。

边界：`SMS_RECEIVED` 只能收「开启之后」的短信，读不到历史记录；部分国产 ROM 需在系统设置里额外允许「短信」权限，双卡或短信被三方 App 接管时可能收不到广播。

## 7. 提醒（`reminder/`）

| 类型 | 请求码 | 时间规则 | 调度 |
| --- | --- | --- | --- |
| 每日 | 1001 | `prefs.reminderTime`（默认 `20:00`） | `scheduleDaily` |
| 周报 | 1002 | 周一 09:00，已过则 +7 天 | `scheduleWeekly` |
| 月报 | 1003 | 每月 1 号 09:00 | `scheduleMonthly` |

- 全部用 `AlarmManager` **一次性闹钟**，触发后由 `ReminderReceiver` 重新排下一次（自续期），而不是 `setRepeating`——规避 Android 12+ 精确闹钟权限与 Doze 漂移。
- `ReminderReceiver` 按 `EXTRA_KIND` 生成日报/周报/月报文案（走 `LedgerRepository` 汇总），通知渠道 `IMPORTANCE_HIGH`，点击进 `MainActivity`。
- 依赖 `SCHEDULE_EXACT_ALARM`（Manifest 已声明）；Android 12+ 用户可能需手动授予"闹钟和提醒"权限，当前代码**没有**引导申请流程。

## 8. 桌面小部件（`widget/LedgerWidgetProvider.kt` 87 行，两规格）

两个 provider：`LedgerWidgetProvider`（2×2「今日收支」，`ledger_widget_info.xml`）与 `LedgerWidgetWideProvider`（4×2「本月概览」，`ledger_widget_wide_info.xml`）。`onUpdate` 与 `onAppWidgetOptionsChanged` 都按 `OPTION_APPWIDGET_MIN_WIDTH >= 180dp` 在 `render(wide = …)` 里选版式，所以钉 2×2 后拖宽会自动切宽版。

- `onUpdate` 先 `goAsync()` 拿 `PendingBroadcast`，再在 `CoroutineScope(SupervisorJob() + Dispatchers.IO)` 里调 `LedgerRepository.widgetTotals(context)` —— 只跑两条 `SUM` 聚合 SQL（本月支出、本月收入）加一条今日支出，**不再全表读**，`finally { pending?.finish() }`。
- 结果写入 `RemoteViews(R.layout.widget_ledger)`：`widget_date`（"MM月dd日"）等，遍历所有 `appWidgetIds` 逐个 `updateAppWidget`。
- 刷新时机：任何写操作（`add/addAll/addImported/update/delete/clear`）后调用 `LedgerWidgetProvider.requestUpdate(context)`。
- `AppWidgetProvider.onUpdate` 在主线程，所以聚合查询必须走 `goAsync()` + IO 协程；主线程只做 `RemoteViews` 拼装。

## 9. 导入 / 导出

### 9.1 CSV（`data/CsvImporter.kt` 268 行）

- 分隔符：比较 `\t` 与 `,` 出现次数自动判定（`detectDelimiter`）。
- 表头识别：含"金额" 且含 时间/日期 且含 收/支 或 "交易类型"。
- 微信账单专属：表头含"交易单号"或"交易类型" → `isWechat=true`，`external_id = "wx:$order"`，`source="微信导入"`；否则 `source="CSV 导入"`。
- 列定位：`timeIdx / amountIdx / typeIdx / tradeTypeIdx / counterpartIdx / productIdx / remarkIdx / orderIdx / categoryIdx / subCategoryIdx`。
- 过滤：交易类型含 `中性`/`不计收支` 跳过；`amount <= 0` 跳过。
- 备注：`交易对方·商品` 拼接，截断 120 字。
- 无表头退化：按 `dateRegex` + `amountRegex` 逐行提取；`isIncome = 含"收入" && !含"支出"`。
- 数值清洗：`parseAmount` 去 `¥￥,`。
- 时间归一：`normalizeTime` 支持 **Excel 日期序列**（20000..80000，基准 `1899-12-30`）——注释特别强调必须用 `Long`：`46345 天 * 86400s` 超出 `Int` 范围。
- 行解析：手写 CSV 状态机（`parseLine`），处理引号内逗号与转义。
- 导出：`esca()` 对 `time/note/source` 做字段转义。

### 9.2 XLSX（`data/XlsxImporter.kt` 93 行）

无第三方库的轻量实现：写临时文件 → `ZipFile` 读 `xl/sharedStrings.xml` + **第一个** `xl/worksheets/sheet*.xml` → 行拼成 CSV → 交给 `CsvImporter.import`。异常统一返回 0。限制：只读首个 sheet，不支持合并单元格/公式求值/日期样式（依赖 Excel 把日期存成序列号）。

### 9.3 导出

`SettingsScreen.kt:954-1114`：时间范围（默认本月 1 号 → 今天，可改）+ 格式单选（`ExportFormat.Csv` / `ExportFormat.Xlsx`）→ 按 `timeMillis` 过滤账单 → 写 `cacheDir/exports/账单_yyyyMMdd_HHmmss.csv|xlsx` → `FileProvider` 取 URI → `Intent.ACTION_SEND` + `EXTRA_STREAM` 拉起系统分享。
**注意**：CSV 带 UTF-8 BOM（Excel 打开不乱码），列 `id,type,category,amount,time,note,source`；XLSX 由 `data/XlsxExporter.kt` 手写 OOXML（inlineStr + 列宽 + 数字金额），列 `时间/类型/分类/金额/备注/来源`。两者共用同一份筛选结果，只是编码器不同。

### 9.4 去重

见 [02 文档第 4 节](02-架构与数据流.md#4-导入去重算法ledgerrepositoryaddimported)：单号优先，其次 `time|金额|type` 指纹。

### 9.5 云备份（WebDAV）

- 组成：`data/WebDavClient.kt`（协议）+ `data/BackupCodec.kt`（编解码）+ `data/BackupRunner.kt`（编排）+ `service/BackupJobService.kt`（定时）。
- 协议：标准 WebDAV（坚果云、群晖、Nextcloud 均可）。`HttpURLConnection` + Basic Auth；`ensureDir` 逐级 `MKCOL`（405 视为已存在），`put` 上传，`download` 取回（404 → null），`list` 用 `PROPFIND Depth:1` 解析 href 尾段。
- 备份内容：`{app, version, exportedAt, count, bills:[{amount,type,category,time,timeMillis,note,source,externalId}]}`；`id` 不导出，恢复时重新自增。
- 文件：固定名 `autoledger-backup.json`（恢复只读它）+ 日备 `autoledger-backup-yyyyMMdd.json`，仅保留最近 7 份。
- 恢复：`decode` → `LedgerRepository.addImported`，走既有 `externalId` / fingerprint 去重，重复不会二次入账（返回新增/跳过数）。
- 定时：`BackupJobService` 每 6h 被系统唤醒，`BackupRunner.autoBackupIfDue` 再按 `AUTO_INTERVAL_MS = 20h` 节流；未配置或未开自动备份直接返回 null，不发网络请求。
- 边界：密码明文存 `dav_pass`（SharedPreferences），备份文件未加密。
