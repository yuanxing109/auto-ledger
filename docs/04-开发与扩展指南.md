# 04 · 开发与扩展指南

## 1. 目录与命名约定

```
app/src/main/java/com/eta/autoledger/
├── AppPrefs.kt            偏好读写（SharedPreferences + mutableStateOf 双向绑定）
├── MainActivity.kt        唯一 Activity 入口
├── data/                  实体 / DAO / 数据库 / 仓库 / 导入器 / 分类
│   ├── LedgerEntity.kt       @Entity + fingerprint/importKey 扩展
│   ├── LedgerDao.kt          @Dao，全部 Flow 或 suspend
│   ├── LedgerDatabase.kt     @Database(version = 2)，单例 + 迁移
│   ├── LedgerDbHelper.kt     旧库 ledger.db（v1），仅用于历史迁移
│   ├── LedgerRepository.kt   object，写操作入口
│   ├── ReportRepository.kt   object，报表聚合
│   ├── CategoryStore.kt      分类定义 + 马卡龙色板
│   ├── CsvImporter.kt        文本账单解析（含状态机）
│   ├── XlsxImporter.kt       轻量 XLSX → CSV 桥
│   └── XlsxExporter.kt       手写 OOXML 导出（inlineStr + 列宽）
├── ui/                    Compose：LedgerApp（壳）+ screen/{Home,Add,Report} + AiScanIcon
├── viewmodel/             HomeViewModel（分页 + 汇总）
├── settings/              SettingsScreen（13 个 SettingsPage 枚举页）
├── screenshot/            MediaProjection / 无障碍 / Root 取图 + VisionHelper + ConfirmEntryReceiver
├── service/               LedgerNotificationListener、SmsReceiver、BillNotifier、UndoBillReceiver、HealthJobService
├── reminder/              ReminderScheduler + ReminderReceiver
├── widget/                LedgerWidgetProvider
├── tile/                  ScreenshotTileService
├── util/                  SystemAccess（系统权限探测 + 一键跳转 + 自愈写回）
└── xposed/                LedgerModule（LSPosed 入口）
```

约定：
- **仓库一律 `object`**，不注入 Context 到构造器，方法第一个参数是 `Context`。
- **Compose 页面文件内聚**：一个页面文件包含自己的私有子组件与颜色常量；不建 `components/` 通用库（除 `AiScanIcon`）。
- **常量就近私有**：颜色 `private val PageBg = Color(...)` 在各文件重复定义，而非集中到主题。这是本项目的现状风格，沿用即可（改动收益低、牵涉面大）。
- Kotlin 代码风格：`kotlin.code.style=official`（`gradle.properties`）。

## 2. 构建与调试

```bash
# 1) 先生成 wrapper（仓库当前缺失，必做一次）
cd "D:/个人项目/auto-ledger"
gradle wrapper --gradle-version 9.4.1

# 2) 之后正常构建
./gradlew :app:assembleDebug
./gradlew :app:installDebug
./gradlew :app:lintDebug        # abortOnError=false，只看报告不阻断
```

环境清单：JDK 17、Android SDK 37（37.2）、Gradle 9.4.1+、KSP 2.3.12、Room 2.8.5。

**调试锚点**
- 日志 TAG：`AutoLedger`（`LedgerNotificationListener`、`LedgerModule`）。
  ```bash
  adb logcat -s AutoLedger
  ```
- 授权状态自检：
  ```bash
  adb shell settings get secure enabled_notification_listeners   # 通知监听是否被授权
  adb shell settings get secure enabled_accessibility_services   # 无障碍是否开启
  ```
- 数据库直查（debug 包）：
  ```bash
  adb shell "run-as com.eta.autoledger sqlite3 databases/auto_ledger.db 'select id,amount,type,category,time_text,timestamp,source,external_id from Bill order by timestamp desc limit 20;'"
  ```
- 截图链路排障顺序：先确认 `ScreenshotAccessibilityService.instance != null`（无障碍已连），再看 `takeScreenshot` 回调是否返回 `ERROR_TAKE_SCREENSHOT_INTERVAL_TIME_SHORT`（连续调用需间隔），最后看 AI 端点是否返回非 2xx。

## 3. 常见改造配方

### 3.1 新增一个分类

1. `data/CategoryStore.kt` 的 `defaults(type)` 列表里加名称；
2. 若需要固定配色，在 `palette` 里加色值（否则按序取模）；
3. **不要**动 `key(type)` 的 `cat_expense/cat_income/cat_other` 键名——已有用户的偏好会读不到而回退默认。

### 3.2 给 `Bill` 加字段（Room v2 → v3）

```kotlin
// 1) LedgerEntity.kt 加字段（给默认值，避免迁移期非空约束报错）
val account: String = ""

// 2) LedgerDatabase.kt：version 2 → 3，并加迁移
@Database(entities = [LedgerEntry::class], version = 3, exportSchema = false)
private val MIGRATION_2_3 = object : Migration(2, 3) {
    override fun migrate(db: SupportSQLiteDatabase) {
        db.execSQL("ALTER TABLE Bill ADD COLUMN account TEXT NOT NULL DEFAULT ''")
    }
}
// databaseBuilder(...).addMigrations(MIGRATION_1_2, MIGRATION_2_3)

// 3) 若字段参与去重，同步改 fingerprint()/importKey()
// 4) CsvImporter / XlsxImporter 的列定位与映射补上
// 5) ReportRepository 若需新维度，扩 ReportAggregate（data class 加默认值，避免全量改调用点）
```

`exportSchema = false`，所以**没有 schema JSON 可用于自动校验**，迁移 SQL 必须手写并自测：装旧版 → 造数据 → 升级安装 → 校验行数与随机页。

### 3.3 换 AI 服务商

`VisionHelper` 假设 OpenAI Chat Completions 形态。适配其它形态的改动点只有两处：
1. `endpoint(prefs.aiBaseUrl, "/chat/completions")` 的路径；
2. 响应取值链 `choices[0].message.content`（当前已兼容 `reasoning_content` / `choice.text` / 根 `content`）。

请求体是 `messages` + `image_url` 的 base64 data URL；若服务商要求 multipart 上传或独立 vision 端点，需重写 `callVisionModel` 的请求构造。

### 3.4 自动记账的扩展点（通知 + 短信，功能已实现）

规则与两条采集通道都已落地（细节见 [03 · 第 6 节](03-功能模块详解.md)）：`data/NotificationRules.kt`（纯函数内核，入口 `parse` / `parseSms`）、`service/LedgerNotificationListener.kt`（通知侧胶水）、`service/SmsReceiver.kt`（短信广播侧胶水）、`service/BillNotifier.kt`（两者共用的通知出口）。

| 需求 | 改哪里 |
| --- | --- |
| 新 App / 新银行 | `NotificationRules` 的 `ALIPAY_PKGS`/`WECHAT_PKGS`/`BANK_PKGS`/`OTHER_PKGS` 加包名，`channelOf` 自动归类 |
| 新短信发送方 | 银行换短号时改 `plausibleSender` 的号码分支；只是换了 106 通道号则补 `FINANCE_HINTS` 关键词 |
| 新噪声词 | 通知用 `BLOCK_WORDS`，短信用 `SMS_BLOCK_WORDS`（两张表刻意分开，否则「可用额度」会误杀真实消费短信） |
| 新分类关键词 | `EXPENSE_KEYWORDS`/`INCOME_KEYWORDS`/`OTHER_KEYWORDS`，键名必须与 `CategoryStore` 里的分类名完全一致 |
| 新收支动词 | `EXPENSE_WORDS`/`INCOME_WORDS`/`STRONG_INCOME_WORDS` |
| 新渠道开关 | `NotifyChannel` 加枚举 + `AppPrefs` 加布尔 + `SettingsScreen` 的 `AutoPage` 加一行 + `isChannelEnabled` 映射 |

注意：
- `parse()` 是纯函数（入参只有文本和三组分类名），可以脱离 Android 直接单测——把真实抓包文本塞进 `NotificationRulesTest` 是最省力的回归方式；
- `externalId` 由「内容指纹 + 金额 + 类型」md5 生成，前缀区分来源（`ntf`/`sms`），重复投递被 `addImported` 唯一索引挡掉；改 `dedupeKey` 会让历史账单失去幂等，慎动；
- 必须保持「包名/发送方白名单 + 关键词」双条件，否则外卖/广告通知、营销短信会污染账本；
- 用户授权仍需手动（设置 → 通知使用权；短信还需「短信记账」开关触发的运行时权限），LSPosed 免授权是另一条路（见 3.5）。

### 3.5 LSPosed 模块落地（写入 `enabled_notification_listeners`）

`scope.list = system`，即 hook `system_server`。可用的挂点：`NotificationManagerService`、`SettingsProvider` 的 `Secure` 表写入。落地顺序建议：
1. `onSystemServerStarting` 里加载目标类（`ClassLoader` 来自 `lpparam.classLoader`）；
2. hook `com.android.providers.settings.SettingsProvider` 的 `call`/`query`，或直接以 system 权限 `ContentResolver.update(Settings.Secure...)` 写入本应用组件名；
3. 覆盖安装后重新写入（监听 `PACKAGE_REPLACED` 不可用，需在 `system_server` 侧判断）；
4. 失败回退：仍引导用户手动授权，模块只做"省一步"。

### 3.6 加一种提醒周期

1. `ReminderScheduler` 加新 `REQ_*` 请求码与 `scheduleXxx()`；
2. `ReminderReceiver` 的 `EXTRA_KIND` 分支加文案生成；
3. `AppPrefs` 加开关键，`SettingsScreen` 的 `Notifications` 页加行；
4. 每次触发后**重排下一次**（现有实现是一次性闹钟自续期，保持这个模式）。

## 5. 建议路线图

1. **修正 P0**：自增主键、README 与实现对齐（或补实现）。
2. **通知监听 → 真实可用**：白名单 + 正则 + `externalId` 幂等 + 设置页开关接线。
