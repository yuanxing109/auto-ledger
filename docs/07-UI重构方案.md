# 自动记账 App · UI 全量重构方案（M3 / Lottie / MPAndroidChart / Compose Icons / LXGW WenKai）

> 目标：把「深色模式不统一、组件各写一套」的现状，换成**一套 design system + 一套图表库 + 一套字体 + 一套图标**。
> 本文所有库版本与坐标均经核实（2026-11-20），核实方式见文末「证据」。

---

## 0. 结论摘要

| # | 决策 | 一句话理由 |
| --- | --- | --- |
| 1 | **Material 3 = 唯一 design system**，Miuix 分三阶段清空 | 现在 `LedgerTheme` 只管 30 个色值，组件/字号/圆角/涟漪仍是 Miuix 与自绘各一套 |
| 2 | **GearUI Kit 不引入** | 它是 KMP + Kuikly 的**渲染引擎**（每个 Compose 节点映射为原生视图），自带 `GearApp` 根与 Navigator；本项目是 Android 原生 Jetpack Compose，引入＝整站换渲染栈，收益只有 iOS |
| 3 | **MPAndroidChart `v4.0.1` 的 `MPChartCompose` 替换三套自绘 Canvas** | 4.0 是 Kotlin 重写 + 官方 Compose 模块（`ChartState`、`animateDataChange`），能干掉 1017 行手绘代码 |
| 4 | **Lottie 只上 4 个动效点** | 其余动效一律 Compose 内建（`animate*AsState` / `AnimatedVisibility` / `Transition`），否则 APK 与耗电一起涨 |
| 5 | **图标改自定义 `AppIcons`（vector drawable）** | `material-icons-extended` 已冻结（不再加新图标、体积数 MB），MiuixIcons 又不能脱离 Miuix；自己收 30 个 SVG 转 vector 最省 |
| 6 | **LXGW WenKai Lite Regular 13.9 MB，必须子集化到 ~2 MB** | 直接打包会让 APK 从 8.9 MB 涨到 20 MB+；且数字/金额不能用它（楷体数字不美观），走 `tnum` 系统等宽 |

**两条路线二选一**（见 §5）：`路线 A 渐进`（保留 Miuix 组件，只换 token + 图表 + 字体，2 周）或 `路线 B 重写`（M3 全量替换 Miuix，6–7 周）。

## 1. 每个库负责什么、用在哪、重叠怎么取舍

### 1.1 总表

| 库 | 版本 / 坐标（已核实） | 负责什么 | 落在哪些文件 | 明确不用在哪 |
| --- | --- | --- | --- | --- |
| Material 3 | `androidx.compose.material3:material3:1.5.0` | 组件与规范：`Scaffold`、`Card`、`ListItem`、`FilterChip`、`ModalBottomSheet`、`TextField`、`Slider`、`Snackbar`、`ColorScheme`/`Typography`/`Shapes` 三套 token | `ui/theme/*`（新建）、所有页面 | 不画图表、不做动效 |
| Jetpack Compose 运行时 | 已随 AGP 9.2.0 / Kotlin 2.4.20 存在 | 布局、状态、`animate*AsState`、`LazyColumn` | 全站 | — |
| Miuix | 0.9.5-beta01（存量） | 现状组件：`MiuixTheme`、`Text`、`Card`、`ArrowPreference`、`SwitchPreference`、`MiuixIcons` | 现有 15 个设置页等 | 迁移完成后**从 classpath 移除** |
| GearUI Kit | `com.gearui:gearui-kit:1.0.0`（Kuikly `2.30.0`） | KMP 跨端 UI（iOS/Android/Web/HarmonyOS），原生渲染 | **不引入**（仅作设计参考） | 与 Compose runtime 互斥 |
| MPAndroidChart | `com.github.PhilJay.MPAndroidChart:MPChartCompose:v4.0.1`（JitPack） | 折线/柱状/环形/组合图，Compose composable + `ChartState` + 数据变更动画 | `ui/screen/ReportScreen.kt`（1017 行 → 约 380 行） | 不做非图表可视化（进度条/环形进度用 Canvas 仍更轻） |
| Lottie | `com.airbnb.android:lottie-compose:6.7.1` | 复杂矢量插画动效（json） | 空状态、保存成功、AI 识图中、报表切换 | 不做按钮点击反馈、不做循环装饰 |
| Compose Icons | 自定义 `AppIcons`（`res/drawable/*.xml`） | 30 个图标：导航、动作、分类徽标、来源 tag | `ui/icons/AppIcons.kt` | 不用 `material-icons-extended`、不混用 `MiuixIcons` |
| LXGW WenKai Lite | `lxgw-wenkai-lite v1.530`，OFL-1.1，Regular 13.9 MB | 中文标题与叙事文案（楷体，辨识度高） | `res/font/lxgw_wenkai_lite.ttf`（子集）+ `ui/theme/Type.kt` | 不用于金额/表格数字（用 `tnum` 等宽）、不用于 12sp 以下正文 |

### 1.2 四组重叠的具体取舍

**① Material 3 vs Miuix（最致命的一组）**
两者都有主题根、`Text`/`Card`/`Switch`、各自 `CompositionLocal`。同时存在会出现：两套 `ContentColor`（M3 的 `LocalContentColor` 与 Miuix 的 `LocalContentColor` 同名不同源）、两套涟漪（M3 `ripple` 跟 `LocalIndication`，Miuix 自绘）、两套最小高度。现状 `LedgerApp.kt` 里已经有 `MiuixTheme.colorScheme.primary` 与自绘 `LedgerTheme.accent` 并存的痕迹。
**取舍：M3 赢，但用一个 `Compat` 期过渡**——`AppTheme` 里同时挂 `MaterialTheme(colorScheme = ledgerColorScheme)` 与 `MiuixTheme(controller = …)`，两者色值都从 `LedgerTheme` 派生，保证颜色只有一个真源；组件替换按页面推进，页面迁完就删掉该页的 `MiuixIcons`/`SwitchPreference` 引用，最后删依赖。

**② GearUI Kit vs 一切**
GearUI 的架构文档写明：页面入口统一走 `GearApp`（每棵页面树只有一个 App 根）、路由走 `Navigator`、组件在 `com.gearui.components.*`、渲染由 Kuikly 把每个节点映射成原生 View，还带自己的 Theme/I18n/Overlay 服务。这和「Activity + `setContent` + Compose runtime + Miuix」是两套互斥的运行时。
**取舍：不引入。** 如果确有 iOS 端计划，正确做法是**在 KMP 工程里用 Kuikly + GearUI 重写整个 App**，那是另一次立项，不是"引入一个组件库"。可以白拿的是它的分层约束（`foundation/tokens → components → app`、组件层禁止硬编码色、页面只挂一个 Theme 根），这三条正是我们现在在补的。

**③ MPAndroidChart vs Compose 内建 Canvas**
现有 `DonutCard` 的环心合计、标签避让、白色缝隙是手写的，MPAndroidChart 的 `PieChart` 原生支持 `setDrawEntryLabels`、`isDrawRoundedSlices`、`isTransparentCircleClippedToSlices`（4.0.1 新增，正好解决"白缝"），但**环心文字要自己叠一层 Box**、标签避让不如手写灵活。
**取舍：折线 + 柱状 + 组合图交给 MPChartCompose（收益最大）；环形图先留自绘**，等 `PieChart` 版式验收通过再换。这样 P1 阶段的风险不集中在一处。

**④ Lottie vs Compose 动画**
规则一句话：**能用一个 `animate*AsState` 表达的，绝不引 Lottie**。Lottie 的适用面只有"多图层路径动画"（扫描光束、空状态插画、勾选打钩）。现状全站 0 个 Lottie 依赖，新增必须走 §2.5 的白名单。

## 2. 统一视觉与组件规范

### 2.1 配色（`LedgerTheme` → M3 `ColorScheme`）

`LedgerTheme` 的双套语义色已经落地（v0.1.6），不改值，只做**映射**：M3 的 `ColorScheme` 需要补齐 `surfaceContainer*` 与 `on*` 系列。

| LedgerTheme | 浅色 | 深色 | M3 槽位 |
| --- | --- | --- | --- |
| `page` | `#F5F7FB` | `#0B0F14` | `surface`（页面底）／`background` |
| `surface` | `#FFFFFF` | `#141A21` | `surfaceContainerLow` |
| `surfaceVariant` | `#EEF2F9` | `#1B232C` | `surfaceContainerHigh` |
| `inset` | `#F0F4FA` | `#10161D` | `surfaceContainerLowest` |
| `border` | `#E4EAF3` | `#242E39` | `outlineVariant` |
| `text` | `#14181F` | `#E8EDF3` | `onSurface` |
| `textSecondary` | `#5B6675` | `#A3AEBD` | `onSurfaceVariant` |
| `textTertiary` | `#8D97A6` | `#7A8798` | `onSurfaceVariant @ 60%` |
| `accent` | `#2563EB` | `#6D9BFF` | `primary` |
| `onAccent` | `#FFFFFF` | `#06101F` | `onPrimary` |
| `income` | `#0B8A5F` | `#34D399` | `tertiary` |
| `danger` | `#DC2626` | `#F87171` | `error` |
| `warning` | `#B45309` | `#FBBF24` | 自定义 `warning`（M3 无此槽，用扩展字段） |
| `chart1..6` | 见 Theme | 见 Theme | 不进 ColorScheme，留在 `LedgerTheme.chartSeries` |

**规则**
1. **单一真源**：只有 `ui/theme/Color.kt` 允许出现 `Color(0x…)`；页面、组件、图表一律引用语义名。
2. **不做动态取色**（Dynamic Color）：记账 App 的"支出/收入/危险"三色必须稳定，壁纸取色会让收入绿变紫。
3. `onXxx` 必须成对：深色 accent 是亮蓝，主色块上的文字必须走 `onPrimary`（`#06101F`），写死白会在深色下糊掉——这条已写进 `docs/04`。
4. 对比度门槛：正文 ≥ 4.5:1、大字（≥18sp bold）与图标 ≥ 3:1；改色值必须跑一遍对比度检查。

### 2.2 字体（LXGW WenKai + 数字等宽）

| 级 | 用途 | 字体 | 字号 / 行高 / 字重 |
| --- | --- | --- | --- |
| Display | 记一笔金额、首页卡片主数字 | **系统等宽**（`FontFamily.Monospace` 或 Inter）+ `tnum` | 34sp / 40sp / Bold |
| Title | 页面标题、卡片标题 | **LXGW WenKai** | 17sp / 24sp / Medium |
| Body | 列表主标题、备注 | LXGW WenKai | 15sp / 22sp / Regular |
| BodyS | 列表副标题（`分类 · 时间 · 来源`） | LXGW WenKai | 13sp / 19sp / Regular |
| Caption | chip、标签、说明 | 系统默认（`sans-serif`） | 11–12sp / 16sp / Regular |

**为什么数字不用 WenKai**：楷体的 `0/6/8` 形态相近、笔画粗细不均，在 34sp 金额上会晃眼，也破坏 `tnum` 的等宽对齐。金额一律 `fontFeatureSettings = "tnum"`。

**子集化（必须做）**：全量 Regular 是 13,949,472 B。用 `fontTools` 裁到「GB2312 6763 字 + ASCII + 记账符号」：

```bash
python - <<'PY'
# 生成字符集：GB2312 全部汉字 + ASCII 可打印 + 记账常用符号
chars = set(chr(i) for i in range(0x20, 0x7F))
for hi in range(0xB0, 0xF8):
    for lo in range(0xA1, 0xFF):
        try:
            chars.add(bytes([hi, lo]).decode('gb2312'))
        except UnicodeDecodeError:
            pass
chars |= set('¥￥±·—…、。，：；！？（）【】《》“”‘’→←↑↓√×÷≈％‰')
open('chars.txt', 'w', encoding='utf-8').write(''.join(sorted(chars)))
print(len(chars))
PY

pyftsubset LXGWWenKaiLite-Regular.ttf \
  --text-file=chars.txt \
  --output-file=app/src/main/res/font/lxgw_wenkai_lite.ttf \
  --layout-features='*' --no-hinting --desubroutinize
```

预期产出 1.8–2.4 MB。**风险兜底**：`fontFamily = FontFamily(Font(R.font.lxgw_wenkai_lite), FontFamily.Default)`，用户备注里的生僻字自动回落到系统字体，不会出豆腐块。

### 2.3 图标（`AppIcons`）

- 统一 24×24 viewport、2dp 描边（filled 用于选中态，outlined 用于未选中）、单色 `tint`。
- 每个图标一个 `res/drawable/ic_*.xml`（vector），在 `ui/icons/AppIcons.kt` 里包成 `val Icons.Rounded.X: ImageVector`。
- **禁止**再新增 `MiuixIcons.XXX` 与 `androidx.compose.material.icons.*` 的混用；迁移期用 `@Deprecated("use AppIcons")` 标记旧引用，让 IDE 帮忙找漏。
- 分类徽标（餐饮/购物/…）现在用 emoji + 色块，保留 emoji（跨设备差异可接受），但底板统一 `color.copy(alpha = 0.18f)`。

### 2.4 图表（MPChartCompose）

| 项 | 规范 |
| --- | --- |
| 颜色 | 主序列 `LedgerTheme.accent`；对比序列 `chart2`；分类环 `chartSeries` |
| 轴 | 只保留左侧 y 轴，`gridColor = LedgerTheme.divider`、`textColor = LedgerTheme.textSecondary`、隐藏右轴与轴线 |
| 网格 | 水平 4 条，虚线 1dp `PathEffect.dashPathEffect(floatArrayOf(4f, 4f))` |
| 触摸 | 高亮点半径 4dp，气泡用 Compose 覆盖层（不用库的 marker，保证主题色一致） |
| 空态 | `isEmpty = true` 时显示「本月还没有数据」+ Lottie 插画，`isLoading` 显示骨架 |
| 动画 | `animateDataChange(newData)`，时长 300ms，切 tab/翻月时启用；首帧不动画 |
| 主题 | `ChartState` 里所有颜色从 `LedgerTheme` 读，切换深浅色时用 `remember(dark)` 重建 estado，避免残影 |

**取舍**：环形图暂留自绘（见 §1.2③）；`ReportScreen.kt` 里 `LineCard`/`BarCard` 换成 `MPChartCompose`，`DonutCard` 保留。

### 2.5 动效（白名单 + 时长曲线）

| 位置 | 手段 | 时长 / 曲线 |
| --- | --- | --- |
| 记一笔保存成功 | Lottie `check_success.json` | 600ms，一次 |
| AI 识别中 | Lottie `scan_beam.json` | 循环，仅识别期间 |
| 首页空态 / 搜索空态 | Lottie `empty_receipt.json` | 静态首帧 + 进入时 400ms |
| 报表 tab 切换 | `animateFloatAsState` + 图表 `animateDataChange` | 300ms `FastOutSlowIn` |
| 列表项出现/删除 | `AnimatedVisibility`（`fadeIn + slideInVertically`） | 220ms |
| 底部 sheet 展开 | M3 `ModalBottomSheet` 内建 | 250ms |
| 按钮按下 | M3 `ripple` | 内建 |

**禁止**：装饰性无限循环动效（耗电 + 分心）、超过 600ms 的过渡、同一屏幕两个以上 Lottie。Lottie 资源必须 `setImagesAssetsFolder(null)` 且**不打包图片资源**（纯矢量 json，单文件 ≤ 60 KB）。

### 2.6 组件清单与统一规则

| 组件 | 规范 | 现状 → 目标 |
| --- | --- | --- |
| 卡片 | M3 `Card`：`shape = 16.dp`、`colors = surface`、`border = 1.dp outlineVariant`、内边距 18dp | 自绘 `ReportCard`/`SettingsCard` → 统一 `AppCard` |
| 列表行 | `ListItem`：高 56dp（双行 72dp）、左图标 24dp + 12dp 间距、右 chevron 20dp | `ArrowPreference` → `AppListRow` |
| 开关行 | `ListItem` + `Switch`（M3） | `SwitchPreference` → `AppSwitchRow` |
| 按钮 | 主：`FilledButton` 高 48dp；次：`OutlinedButton`；幽灵：`TextButton` | 键盘「完成/再记一笔」三态已按此改 |
| chip | `FilterChip` 高 32dp、圆角 16dp；选中 `primary` 底 + `onPrimary` 字 | 搜索页三处 chip |
| 输入框 | 44dp 高、`surfaceContainerHigh` 底、圆角 12dp、focus 2dp `primary` | `BasicTextField` 包装成 `AppTextField` |
| 弹层 | `ModalBottomSheet` 顶角 24dp + drag handle | `FilterSheet` 自绘 Dialog → M3 Sheet |
| 空状态 | 图标/插画 96dp + 标题 Title + 副文案 BodyS + 主按钮 | 新增 `AppEmptyState` |
| 反馈 | `Snackbar`（替代 Toast 做可撤销操作） | 「已撤销这笔自动记账」改 Snackbar + Undo |

**五条硬规则**
1. 间距只用 4 的倍数（4/8/12/16/20/24），圆角只用 4 档（8/12/16/24）。
2. 触控目标 ≥ 48dp（chip 用 `minimumInteractiveComponentSize` 撑开）。
3. 一套主题根：`AppTheme` 是唯一挂 `MaterialTheme` 的地方，页面不自己挂。
4. 不许 `Color(0x…)`（CI 加 `grep` 门禁，见 §3.5）。
5. 文案层级固定：`Title` 说明"这是什么"，`BodyS` 说明"什么时候/什么分类"，不重复。

## 3. 分阶段迁移顺序

### 3.1 总览

| 阶段 | 内容 | 页面/文件 | 预估 | 产出验收 |
| --- | --- | --- | --- | --- |
| **P0 地基** | 字体子集、`AppTheme`（M3+Miuix 并存）、`AppIcons`、`ChartState` 封装、Lottie 依赖与 3 个 json、CI 色值门禁 | `ui/theme/*`、`ui/icons/*`、`ui/chart/*`、`res/font`、`res/raw` | 4–5 天 | 不动任何页面外观；APK 体积增量 ≤ 2.5 MB |
| **P1 报表试点** | `LineCard`/`BarCard` → MPChartCompose；`PeriodRow`/`SummaryCard` → M3 组件 | `ui/screen/ReportScreen.kt`（1017 → ~380 行） | 3–4 天 | 三张图在深浅色下与旧版构图一致；触摸/动画正常 |
| **P2 首页 + 记一笔** | `HomeScreen`（摘要卡、列表行、预算卡）、`AddScreen`（金额区、键盘、分类网格）、`SearchScreen`（chip → FilterChip、Sheet → ModalBottomSheet） | 3 个文件 | 5–6 天 | 列表滚动 60fps；键盘无跳动 |
| **P3 设置 15 页** | `SettingsUi.kt` 的 5 个 internal 组件换成 M3 等价物；`ArrowPreference`/`SwitchPreference` 全部替换 | `settings/*`（8 个文件） | 6–8 天 | 15 页视觉一致；无 Miuix import |
| **P4 收尾** | 空态/动效/无障碍/深色逐页走查；删 Miuix 依赖；文档与截图更新 | 全站 | 3–4 天 | `grep -r "miuix"` 为空 |

**为什么 P1 先动报表**：它 1017 行、只依赖 `ReportRepository`，与其他页面零耦合，是"换图表库"最小的验证面；同时它也是当前深浅色问题最刺眼的一页（顶栏白条、图表被底栏切）。

**为什么 P3 最后**：15 个页面 + 1460 行主文件 + `SettingsUi` 的 internal 组件是最大的耦合面，前面阶段沉淀的 `AppListRow`/`AppSwitchRow`/`AppCard` 正好在 P3 一次用上，避免反复改。

### 3.2 P0 关键动作（不动外观，只铺路）

1. `res/font/lxgw_wenkai_lite.ttf`（子集）+ `ui/theme/Type.kt` 定义五级 `Typography`。
2. `ui/theme/Theme.kt`：`@Composable fun AppTheme(dark: Boolean, content)` 内挂 `MaterialTheme(colorScheme = ledgerScheme(dark), typography, shapes)`，并把 `LedgerTheme.dark = dark`；**保留** `MiuixTheme` 外壳（`MiuixTheme(controller)` 包在外层），直到 P4。
3. `ui/icons/AppIcons.kt` + 30 个 vector。
4. `ui/chart/`：`AppLineChart(state)`、`AppBarChart(state)` 两个 wrapper，内部固定轴/网格/文字样式，页面只传 `List<Point>`，避免各页写两遍样式。
5. CI 加门禁（`.github/workflows/android.yml` 增加一步）：
   ```yaml
   - name: forbid hardcoded colors
     run: |
       if grep -rn "Color(0x" app/src/main/java --include=*.kt | grep -v "ui/theme/"; then
         echo "::error::硬编码颜色必须放进 ui/theme/"; exit 1
       fi
   ```
6. Lottie：`implementation("com.airbnb.android:lottie-compose:6.7.1")` + 3 个 json（`check_success` / `scan_beam` / `empty_receipt`），并封一个 `AppLottie(rawRes, modifier)` 统一深浅色着色（`LottieProperty.COLOR_FILTER`）。

### 3.3 P1/P2/P3 的替换对照

| 旧 | 新 | 备注 |
| --- | --- | --- |
| `ReportCard`（自绘 Column + background + border） | `AppCard`（M3 `Card`） | 圆角 16、描边 1dp |
| `LineCard`（Canvas 折线 + 拖动气泡） | `AppLineChart` + Compose 覆盖层气泡 | 气泡逻辑保留（MPChart 的 marker 是 View 体系） |
| `BarCard` | `AppBarChart` | 圆角柱用 4.0 的 `isRoundedBars` |
| `DonutCard` | **暂不换** | 环心合计/标签避让仍自绘 |
| `SummaryCell` | `AppStat`（label + value + 语义色） | 负数/正数配色规则不变 |
| `ArrowPreference` | `AppArrowRow` | chevron 20dp |
| `SwitchPreference` | `AppSwitchRow` | M3 `Switch` |
| `SettingsCard` | `AppCard` | — |
| `BasicTextField` 各处 | `AppTextField` | 统一 44dp/12dp/2dp focus |
| `FilterSheet`（Dialog） | `ModalBottomSheet` | 拖拽手柄 + 24dp 顶角 |
| Toast | `Snackbar`（仅可撤销/可重试） | 其余轻提示保留 Toast |

### 3.4 风险点（按后果排序）

| 风险 | 触发条件 | 后果 | 处置 |
| --- | --- | --- | --- |
| **Miuix 与 M3 双主题并存期** | P0–P3 期间两套 `CompositionLocal` 同时挂 | 文字色/涟漪不一致、偶发色差 | 颜色只从 `LedgerTheme` 派生进两套；`AppTheme` 唯一入口；每页迁完删对应 Miuix 引用 |
| **MPChartCompose 是 4.0 新模块** | API 与我们需求（气泡自定义、环心文字）不匹配 | 某张图要回退自绘 | P1 只换折线+柱状；环形留自绘；封装层 `AppLineChart` 保证可替换 |
| **JitPack 可用性** | CI 冷缓存 + 网络抖动（历史上 aliyun 镜像 502） | 构建失败 | `settings.gradle.kts` 显式加 `maven("https://jitpack.io")`；CI 中不放镜像；`MPChartCompose` 下载失败时 `--refresh-dependencies` 重试一次 |
| **字体子集漏字** | 用户备注含 GB2312 外字符 | 豆腐块 | `FontFamily(自定义字体, FontFamily.Default)` 回落；发布前用真实 1688 条账单跑一遍缺字检测脚本 |
| **APK 体积** | 字体 2 MB + Lottie json + MPChart | 8.9 MB → 12 MB | Lottie 单文件 ≤ 60 KB；`isShrinkResources` 在 release 打开；对 json 用 `optimizeLottie`（可选） |
| **Lottie 深色适配** | json 里写死颜色 | 深色下白底插画 | `AppLottie` 统一 `COLOR_FILTER`；资源制作规范：只用 `#000000` 占位色 |
| **图表在 `LazyColumn` 内** | 滚动复用 + 触摸冲突 | 高亮跳动、滑动被吃 | 图表放在非 lazy 的 Column 内（现状报表页就是 `verticalScroll`），或用 `nestedScroll` 让横向拖动优先 |
| **Kotlin/Compose 版本** | M3 1.5.0 需要较新 compose compiler | 编不过 | 现 Kotlin 2.4.20 + AGP 9.2.0 已满足；M3 用 1.5.0 不要跳 alpha |
| **无障碍退化** | 自绘 Canvas 无语义 | 读屏读不到图表 | MPChart 提供 View 语义；自绘部分补 `contentDescription`；P4 用 TalkBack 走查 |

## 5. 路线 A / B 对照（选一个）

| 维度 | 路线 A：渐进（推荐） | 路线 B：M3 全量重写 |
| --- | --- | --- |
| 范围 | token 统一 + MPChart + Lottie + 字体 + AppIcons；**Miuix 组件保留** | 全部替换为 M3，删 Miuix，15 页重写 |
| 工期 | 2–2.5 周 | 6–7 周 |
| 解决"全局不统一" | 颜色/字体/图表/图标统一；**组件高度与涟漪仍为 Miuix 风格** | 彻底统一 |
| 风险 | 低（不碰设置页结构） | 高（1460 行主文件 + 15 页 + Preference 语义） |
| 收益 | 视觉 80% 统一，改动可回滚 | 视觉 100% 统一，长期维护成本最低 |
| 适合 | 现在的主要痛点是"颜色/字体/图表乱" | 目标是长期产品化、还要加主题换肤 |

**建议**：先走 A，把 P0 + P1 做完（约 1 周），拿到"图表换库 + 字体统一"的实际观感；如果那时仍觉得组件层级不一致，再执行 P2–P4 转 B。**不要**一开始就双线并行——Miuix 与 M3 同时改会让每个 PR 都碰到两套主题。
