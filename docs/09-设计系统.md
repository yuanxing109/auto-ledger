# 自动记账 App 设计系统（Design System）

> 产品：面向普通用户的个人自动记账 App（iOS / Android）
> 行业：fintech / personal finance / automated bookkeeping
> 技术载体：Compose Multiplatform + Miuix（`top.yukonga.miuix.kmp`）
> 唯一真源：`ui/theme/LedgerPalette.kt`（色）、`LedgerTextStyles.kt`（字）、`LedgerDimens.kt`（距）
> 本文与代码一一对应，token 名直接采用 `LedgerColors` 字段名。

## 0. 2026-11 视觉重塑定稿

本轮以“低饱和、轻层级、数字优先”为准，以下规则覆盖后文旧色值说明：

- **主色**：浅色 `accent = #3B74D0`，深色 `accent = #7898D2`。主色用于主按钮、选中态、图表主线和核心金额。
- **金额语义**：收入/正结余使用 `income = #399E75`，深色 `#70C39D`；支出/负结余使用 `expense = #D16158`，深色 `#E18B83`；错误与删除使用更深的 `danger = #C6534D`，深色 `#D97870`。
- **通用卡片**：所有普通卡片使用 `ThemeSurfaceCard`。浅色为 75% 白玻璃 `glassCard = #BFFFFFFF`，深色为 75% 深灰 `#BF171D25`；1dp `borderSoft` 描边，2dp 柔和阴影。
- **阴影**：只允许 `cardShadow = #0D000000` 这类带透明度的语义色。禁止纯黑实心阴影；组件默认调用 `shadow(elevation = 2.dp, ambientColor = LedgerTheme.cardShadow, spotColor = LedgerTheme.cardShadow)`。
- **首页核心卡**：使用不透明语义表面 `raisedCard`（浅色白、深色 `#1C222A`），不再使用整版蓝色渐变。核心金额使用 `heroAmountStyle()`，26sp、700、`tnum`，颜色为 `accent`。
- **圆角分级**：大模块容器/月报卡/设置组卡使用 `LocalDimens.current.radiusCard = 16.dp`；内部小条目、单条账目与输入框使用 `radiusSmall = 12.dp`；标签/小按钮使用 `LedgerDimens.radiusSm = 8.dp`。
- **分组规则**：设置首页只保留两张大组卡，内部用 `divider` 分行；不再为每个入口各建一张独立卡片，也不保留品牌色大横条。
- **导航规则**：三向底栏结构不变，中间“记一笔”为 52dp 悬浮圆形主按钮；报表周/月/年切换使用文字加粗和极淡主色底，不再使用粗蓝色下划线。

## 1. 风格方向

**主风格：Minimalism & Swiss Style（极简 / 瑞士国际主义）**

选择理由：
1. **任务决定风格**——自动记账是"高频扫一眼"的效率工具，不是内容消费产品。用户打开 App 的 3 秒内要回答两个问题：*这个月花了多少？哪里花得多？* 瑞士风格的网格、留白、强对比、字体层级正好服务"数据优先、装饰归零"。
2. **信任感来自秩序而非炫技**——记账涉及钱，克制、可预测、无渐变无玻璃的界面比任何动效都更让人放心。
3. **可无障碍、低性能成本**——`cost:low / drivers:none`，弱机型也不掉帧；对比度、键盘/读屏、明显焦点全部可满足。
4. **与现有 Miuix 单源架构天然契合**——Miuix 本身就是 Material 式的克制体系，无需另起炉灶。

不选的其他方向（仅作对照）：Glassmorphism（装饰性玻璃卡片拖慢操作、降低对比）、Neumorphism（软阴影对比不足，数字难读）、Brutalism / 大色块（淹没核心数据）、Dark Luxury（金色奢华与工具属性冲突）。

**一句话风格定义**：冷灰白底 + 半透明卡片分层 + 低饱和柔蓝强调；数字最大、轻阴影分层、信息密度可调；柔和砖红只谈支出，柔和绿只谈收入与正结余。

## 2. 色彩系统（语义 Token）

规则：**红 = 支出 / 警示；绿 = 收入；灰 = 中性；蓝 = 品牌强调与可交互；琥珀 = 预算临界**。颜色永远不单独承载语义，必须配 `+ / −` 号或「收入 / 支出」文字（照顾色盲）。

### 浅色（Light）

| Token（LedgerColors 字段） | Hex | 用途 | 对比度（vs 白底） |
|---|---|---|---|
| `page` | #F5F7FB | 页面底（冷灰，不用纯白刺眼） | — |
| `surface` | #FFFFFF | 卡片 / 列表表面 | — |
| `surfaceVariant` | 黑 10% 叠色 | 次级块、进度槽底 | — |
| `inset` | 黑 7% 叠色 | 输入框内凹底、分组底 | — |
| `border` | 黑 ~47% 叠色（`0x770B1220`） | 可交互边界（按钮/chip/输入框/选中态，1dp） | ≥3:1 ✅ |
| `borderSoft` | 黑 ~12% 叠色（`0x1F0B1220`） | 装饰性卡片外框（不受 3:1 约束） | — |
| `divider` | 黑 8% 叠色 | 分隔线 | — |
| `text` | #14181F | 主文字、金额 | 17.79:1 ✅ |
| `textSecondary` | #5B6675 | 次要说明、时间 | 5.83:1 ✅ |
| `textTertiary` | #8D97A6 | 占位符 / 极弱提示（**仅限 ≥18sp 或非关键信息**） | 2.95:1 ⚠️ |
| `glassCard` | 白 75% | 普通半透明卡片表面 | — |
| `raisedCard` | #FFFFFF | 首页核心资产卡实色表面 | — |
| `cardShadow` | 黑 5% | 卡片 2dp 柔和投影 | — |
| `accent` | #3B74D0 | 主按钮、可点文字、选中态、图表主线、核心金额 | 4.56:1 ✅ |
| `accentPressed` | #315FA9 | 主按钮按下态 | — |
| `onAccent` | #FFFFFF | 蓝底上的文字/图标 | 5.17:1 ✅ |
| `income`（收入/正结余绿） | #399E75 | 收入金额、正结余、收入徽标 | 4.52:1 ✅ |
| `expense`（支出/负结余砖红） | #D16158 | 支出金额、负结余、负向变化 | 4.54:1 ✅ |
| `danger`（错误/删除红） | #C6534D | 错误、删除、超支 | 4.71:1 ✅ |

> **预算语义映射**：预算「剩余充足」= `accent`（蓝，不用绿，绿色专属收入）；「接近上限（≥80%）」= `warning`；「已超支」= `danger`。这样"绿=收入"这条全局规则不被预算打破。

### 关键约束落地
- 柔和砖红 `#D16158` 用于支出金额与负结余；`#C6534D` 只用于错误、删除与超支。
- 柔和绿 `#399E75` 只用于收入金额、正结余、收入标签/徽标。
- 灰色层级（`textSecondary`/`textTertiary`/`border`）承载所有中性信息。
- 图表 6 色为柔蓝/柔绿/琥珀/青/玫红/砖红（`#3B74D0 / #399E75 / #F59E0B / #0891B2 / #DB2777 / #D16158`），避开与强调蓝混淆的紫色系，同时保证 6 类可区分。

### 尺寸 Token 双命名对照（速查；间距/圆角规范见 §4）

`LedgerDimens` 有**两套命名**：`companion object` 里的静态常量，与 `data class` 的实例字段。二者**不总是一一对应**，且名字相近者含义可能不同。

**写代码前先查这张表，禁止凭记忆写 `LocalDimens.current.radiusDialog` 或 `LocalDimens.current.minTouch`。**

| 用途 | companion 常量 | 实例字段 | 正确调用方式 |
|---|---|---|---|
| 极紧间距（图标与文字） | `LedgerDimens.xs` = 4dp | **无** | `LedgerDimens.xs` |
| 紧凑间距（同级元素） | `LedgerDimens.sm` = 8dp | **无**（`gapSmall` = sm） | `LedgerDimens.sm` 或 `LocalDimens.current.gapSmall` |
| 标准间距（文字与图标） | `LedgerDimens.md` = 12dp | **无**（`gap` = md） | `LedgerDimens.md` 或 `LocalDimens.current.gap` |
| 宽松间距（卡片内边距） | `LedgerDimens.lg` = 16dp | `cardPadding` / `pagePadding` = lg | `LocalDimens.current.cardPadding` |
| 分区间距 | `LedgerDimens.xl` = 24dp | **无**（`gapLarge` = xl） | `LedgerDimens.xl` 或 `LocalDimens.current.gapLarge` |
| 大分区间距 | `LedgerDimens.xxl` = 32dp | **无** | `LedgerDimens.xxl` |
| 最小触摸区域 | `LedgerDimens.minTouch` = 48dp | **无** ⚠️ | `LedgerDimens.minTouch` |
| 小圆角（键帽、小标签、小按钮） | `LedgerDimens.radiusSm` = **8dp** | `radiusSmall` = **12dp** ⚠️ | `LedgerDimens.radiusSm` |
| 中圆角（单条账目、输入框、小条目） | `LedgerDimens.radiusMd` = 12dp | `radiusSmall` = 12dp | `LocalDimens.current.radiusSmall` |
| 大圆角（标准卡片） | `LedgerDimens.radiusLg` = 16dp | **无** | `LedgerDimens.radiusLg` |
| 大模块容器（设置组卡、月报卡） | `LedgerDimens.radiusLg` = 16dp | `radiusCard` = radiusLg | `LocalDimens.current.radiusCard` |
| 弹层圆角（对话框） | `LedgerDimens.radiusDialog` = **28dp** | `radiusSheet` = **radiusDialog = 28dp** | `LocalDimens.current.radiusSheet` ⚠️ |
| 胶囊圆角 | **无** | `radiusCapsule` = 50dp | `LocalDimens.current.radiusCapsule` |
| 默认尺寸集 | `LedgerDimens.default` | — | `LocalDimens.current`（= default） |

#### 三个必记陷阱

| 陷阱 | 错误写法 | 正确写法 | 已踩坑 |
|---|---|---|---|
| `radiusDialog` 是常量不是实例字段 | `LocalDimens.current.radiusDialog` | `LocalDimens.current.radiusSheet` | §11 |
| `minTouch` 是常量不是实例字段 | `LocalDimens.current.minTouch` | `LedgerDimens.minTouch` | §15 |
| `radiusSm`(8dp) ≠ `radiusSmall`(12dp) | 以为 `radiusSmall` 是 8dp | `radiusSmall` 实际 = `radiusMd` = 12dp | §8 |

#### 判据

1. **实例字段优先**：能用 `LocalDimens.current.xxx` 就用（支持未来换肤换尺寸）。
2. **常量兜底**：实例字段不存在时用 `LedgerDimens.xxx`（静态，不随主题变化）。
3. **不确定就查表**，不要猜命名规律——`radiusSmall` 绑 `radiusMd` 而非 `radiusSm` 就是反直觉的。

## 3. 字体系统

**组合**：系统无衬线（Sans）为主 + **数字等宽（tabular figures, `tnum`）**。
- 中文标题/正文：系统默认 Sans（Android: MiSans/Roboto；iOS: PingFang SC）。可选品牌标题接入 LXGW 文楷，**仅标题**。
- **金额/数字永不换字体**，始终系统 Sans + `fontFeatureSettings = "tnum"`；楷体/手写体在 34sp 上 0/6/8 难分辨，记账金额不能有歧义。
- 数字一律右对齐、等宽，避免滚动时金额左右跳动。

### 字号层级（对应 `LedgerTextStyles` 槽位，sp / 行高 / 字重）

| 角色 | 槽位 | 字号/行高 | 字重 | 用法 |
|---|---|---|---|---|
| 主金额（本月总支出） | `amountDisplayStyle()`（**不占 headline1**） | 34 / 42 | Bold + tnum + End | 首页第一视觉 |
| 次金额（收入/结余/大卡内数字） | headline2 | 28 / 34 | Bold + tnum | 大卡片 |
| 页面标题 | title1 | 22 / 28 | Bold | 顶栏 |
| 区块标题 | title2 | 20 / 26 | SemiBold + tnum | 分组头 |
| 列表项标题 | title3 | 17 / 23 | SemiBold | 交易名/分类名 |
| 正文 | body1 | 15 / 22 | Regular | 说明、正文 |
| 表单/小标题 | title4 | 15 / 21 | Medium | 字段标题 |
| 副标题 | subtitle | 14 / 20 | Medium | 次级标签 |
| 按钮文字 | button | 15 / — | Medium | 按钮 |
| 次要正文 | body2 | 13 / 19 | Regular | 时间、备注 |
| 辅助说明 | footnote1 | 12 / 16 | Regular | 标签 |
| 极小注 | footnote2 | 11 / 15 | Regular | 角标、极弱提示 |

> `headline1` **不覆盖**（Miuix 列表行/偏好项标题内部读的就是 `headline1`）；大金额一律走 `amountDisplayStyle()`，不要用 `textStyles.headline1`。

> 规则：页面里只允许引用上表槽位，禁止写 `fontSize = 13.sp` 这类一次性字号（`check-ui-consistency.sh` R4/R5 会统计）。

## 4. 间距与栅格（8pt 系统）

基准 **8dp**，允许 4dp 半档做微调；所有间距/圆角只从下表取，禁止魔法数（如 `13.dp`）。

| Token | 值 | 用途 |
|---|---|---|
| `space.xs` | 4dp | 图标与文字之间 |
| `space.sm` | 8dp | 同级元素、紧凑 |
| `space.md` | 12dp | 文字与图标、标签行 |
| `space.lg` | 16dp | 卡片内边距、页面左右边距 |
| `space.xl` | 24dp | 区块与区块之间 |
| `space.xxl` | 32dp | 大分区间（可选） |
| `radius.sm` | 8dp | 键帽、小标签 |
| `radius.md` | 12dp | 输入框、小卡片 |
| `radius.lg` | 16dp | 中卡片 / 元素 |
| `radius.card` | 16dp | 大模块容器、设置组卡、月报卡 |
| `radius.small` | 12dp | 单条账目、输入框、内部小条目 |
| `radius.sm` | 8dp | 标签、小按钮、键帽 |
| `radius.xl` | 24dp | 保留给底部面板等特殊容器 |
| `radius.dialog` | 28dp | 对话框 |
| `radius.capsule` | 50dp | 胶囊按钮、chips |

**栅格**：移动端单列，左右安全边距 16dp；卡片内 16dp；卡片间距 12dp；垂直分区 24dp。触摸元素最小 48dp 高，相邻可点元素间距 ≥ 8dp。

### 4.1 间距判据（歧义裁决规则）

当同一个数值可以归入两个档位时（典型：`20dp` 既能算「紧」也能算「块」），按下表判定，不再逐次讨论：

| 场景 | 取值 | 说明 |
|---|---|---|
| **卡片 / 弹窗内边距** | **16dp**（紧档） | 内容与容器边缘的距离 |
| **卡片 / 弹窗外边距** | **24dp**（块级） | 容器与容器、容器与屏幕边缘的距离 |
| **分区间距** | **24dp** | 两个语义区块之间 |
| **行内间距** | **8dp** | 同一行内相邻元素（图标与文字、标签与数值） |
| **标题与内容间距** | **12dp** | 区块标题与其下方内容 |
| **标签与内容间距** | **8dp** | 字段名与字段值 |

**圆角**：必须走 `LocalDimens` / `LedgerDimens` token。大模块统一 `radiusCard = 16dp`，内部条目统一 `radiusSmall = 12dp`，标签与小按钮统一 `LedgerDimens.radiusSm = 8dp`。**禁止 `RoundedCornerShape(N.dp)` 一次性字面量**。合法阶梯字面量仅限 `4 / 8 / 12 / 16 / 24 / 32 / 50`（`50` 为胶囊），且优先用 token；`tools/check-ui-consistency.sh` 的 R6 会拦截其余值。

**细线豁免**：当元素**高度 ≤ 6dp** 时，`RoundedCornerShape(N.dp)` 的 N 允许为「高度的一半」，不受 4/8/12/16/24/32/50 阶梯约束。这类元素是细线/拖拽把手/下划线，不是容器。已确立 2 处：
- `LedgerApp.kt` 报表页签选中下划线（3dp 高，圆角 2dp）
- `SearchScreen.kt` FilterSheet 拖拽把手（4dp 高，圆角 2dp）

**功能值豁免**：以下不属于间距，不参与阶梯映射，可用任意值并需注释说明——
- Canvas 绘图坐标（`toPx()` 转换的半径、线宽、折点偏移）
- 组件尺寸（图标 `size`、头像圆、装饰圆）
- 容器约束（`maxWidth`、`heightIn(max)`、`minHeight` 组件内部参数）
- 对齐计算值（如「图标列宽 = 40 图标 + 12 间距 + 14 偏移」）
- 底部留白 `82dp`（= 底栏 72 + 缓冲 10）

|---|---|

## 6. 暗黑模式映射

近黑分档 `page < inset < surface < surfaceVariant`，**不用纯黑 #000000**（OLED 亮度抖动 + 阴影不可见，改用 `border` 描边分层）。

## 7. 无障碍策略

1. **触控目标**：iOS 最小 44×44pt，Android 最小 48×48dp；图标按钮实际可点区不小于该值（视觉可 24dp，热区补 padding）。
2. **文字对比度**：正文 ≥ 4.5:1；大号文字（≥18pt / ≥14pt Bold，约 24sp / 18sp 粗）≥ 3:1。`textTertiary`（2.95:1）只能用于占位符或 ≥18sp 非关键信息，**不得作正文**。
3. **不只靠颜色**：收支同时用 `+ / −` 号 + 「收入 / 支出」文字或图标；预算状态用图标 + 文案，色盲用户可辨。
4. **金额可读**：等宽数字、右对齐、千分位；TalkBack/VoiceOver 语义读作「支出，一百二十八元」而非逐字符。
5. **焦点可见**：键盘/读屏导航时有 2dp `accent` 外环 + offset，不做低对比描边。
6. **动效**：尊重"减少动态"系统设置；金额不做滚动/跳动动画，仅 120–200ms 的按压/展开过渡。
7. **字号缩放**：支持系统字体缩放 200%，用 sp 不用 dp 定字；布局允许换行不截断关键金额。
8. **对比度自检**：新增色必须跑对比度脚本（本仓库 `tools/` 或本文表格口径），未过 4.5:1 不进正文。

## 8. 反模式清单（本项目严格避免）

1. ❌ **高饱和蓝大面积铺底 / 装饰性渐变**：首页核心卡使用 `raisedCard` 实色表面，金额单独用柔蓝强调。
2. ❌ **网页式 Hero 大横幅 / 营销排版**：记账 App 没有"首屏营销区"，首页第一行就是数据。
3. ❌ **碎片化卡片墙**：设置入口必须归入大组卡，内部用分割线；禁止每个入口单独占一张卡。
4. ❌ **大色块淹没核心数据**：不用整块蓝/绿背景压住数字；数字使用主色/语义色，背景永远退后。
5. ❌ **红绿单独表意**：必须配 `+ / −` 或文字，照顾红绿色盲。
6. ❌ **纯黑 #000 大面积底**：用近黑 #0B0F14，避免 OLED 抖动与阴影失效。
7. ❌ **金额用手写体 / 非等宽字体**：会造成 0/6/8、1/7 误读。
8. ❌ **`textTertiary` 当正文**：2.95:1 不合格，只做占位/弱提示。
9. ❌ **一次性魔法数**：禁止 `padding(13.dp)`、`RoundedCornerShape(14.dp)`，只能取 §4 阶梯。
10. ❌ **把本月总额/分类占比藏进二级页**：首页必须一眼可见"这个月花了多少、哪里花得多"。
11. ❌ **打断式弹窗/toast 记录账**：补记与修正用行内编辑或底部面板，不打断浏览。
12. ❌ **无意义的滚动数字动画 / 视差**：记账要快，动效只用于状态反馈。
13. ❌ **用绿色表示"预算充足"**：绿色语义锁定收入；预算用蓝剩余 / 琥珀临界 / 红超支。
14. ❌ **同屏两种以上强调色抢焦点**：一屏只允许一个主强调（蓝），红绿只在金额语义处出现。
