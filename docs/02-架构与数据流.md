## 2. 数据模型

### 2.1 Room 实体（`data/LedgerEntity.kt:47`）

```kotlin
@Entity(
    tableName = "Bill",
    indices = [Index(["timestamp"]), Index(["external_id"], unique = true)],
)
data class LedgerEntry(
    @PrimaryKey(autoGenerate = true) val id: Long = 0L,
    val amount: Double,
    val type: String,          // expense / income / other
    val category: String,
    @ColumnInfo("time_text") val time: String,        // 展示用文本时间
    @ColumnInfo("timestamp") val timeMillis: Long = 0L, // 排序/聚合真源
    @ColumnInfo("remark") val note: String,
    val source: String,
    @ColumnInfo("external_id") val externalId: String? = null,
    @ColumnInfo("is_recurring", defaultValue = "0") val isRecurring: Boolean = false,
    @ColumnInfo("recurring_rule") val recurringRule: String? = null,
)
```

关键设计（文件注释原文要点）：

- **主键改自增**：旧实现用 `System.currentTimeMillis()` 当主键，快速连记会撞键 + `REPLACE` 静默覆盖丢账。改自增后由 SQLite 保证唯一。
- **`external_id` 唯一索引**：自动记账/导入的去重闸门；`null` 不受唯一约束限制（手动记账不写 externalId）。
- **模板行**：`isRecurring=true` 的行是周期规则模板，**入库但不参与任何统计**（DAO 全部 `WHERE is_recurring = 0`）。`RecurringWorker` 到点后生成实账时 `recurringRule = null`、`source = "recurring"`。

DDL（Room 生成，对应 v3）：

```sql
CREATE TABLE IF NOT EXISTS Bill (
  id INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
  amount REAL NOT NULL, type TEXT NOT NULL, category TEXT NOT NULL,
  time_text TEXT NOT NULL, timestamp INTEGER NOT NULL,
  remark TEXT NOT NULL, source TEXT NOT NULL,
  external_id TEXT, is_recurring INTEGER NOT NULL DEFAULT 0, recurring_rule TEXT
);
CREATE INDEX index_Bill_timestamp ON Bill(timestamp);
CREATE UNIQUE INDEX index_Bill_external_id ON Bill(external_id);
```

### 2.2 `external_id` 与唯一索引的陷阱

- `external_id` 无法在列级 `UNIQUE`（Room 要命名索引），只能在 `indices` 里声明 `unique = true`。
- **历史脏数据风险**：若旧库已存在重复 `external_id`，`MIGRATION_1_2` 的 `CREATE UNIQUE INDEX` 会抛异常导致首启崩溃。上线前应先对旧库去重（见 [04 已知问题](04-开发与扩展指南.md#4-已知问题清单)）。
- **毫秒级 key 的坑**：`external_id = hash(pkg|title|text|bigText|postTime)`，含毫秒 `postTime`；同一条短信被重复投递时 postTime 差几毫秒 → external_id 对不上 → 双写。故在自动记账入口额外叠了 `ParseDedup`（分钟级指纹，见 §4）。

### 2.3 DAO（`data/LedgerDao.kt:278`）

投影类：

| 类 | 字段 |
| --- | --- |
| `Bucket` | `bucket: String`, `total: Double`（按 `strftime` 分桶聚合） |
| `CategoryAgg` | `name: String`, `total: Double`, `count: Int` |
| `TotalsRow` | `@ColumnInfo("cur_amount") current`, `prev_amount` previous, `exp_amount` expense, `inc_amount` income（一次扫描拿本期/上期/支出/收入） |
| `Summary` | `todayExpense`, `monthExpense`, `monthIncome` |
| `ImportRow` | `externalId`, `time`, `amount`, `type`, `timestamp` |

关键查询：

```sql
-- 全量（Flow）
SELECT * FROM Bill WHERE is_recurring = 0 ORDER BY timestamp DESC, id DESC
-- 翻页（offset 版，首页首屏用）
SELECT * FROM Bill WHERE is_recurring = 0 ORDER BY timestamp DESC, id DESC LIMIT :limit OFFSET :offset
-- keyset 游标（pageBefore，避免深翻页 OFFSET 扫行）
SELECT * FROM Bill WHERE is_recurring = 0
  AND (timestamp < :cursorTime OR (timestamp = :cursorTime AND id < :cursorId))
  ORDER BY timestamp DESC, id DESC LIMIT :limit
-- 计数
SELECT COUNT(*) FROM Bill WHERE is_recurring = 0
```

搜索：`search(...)` + `countSearch(...)` 用 `categoryMode`（0=不限、1=包含）+ 分类列表；**空分类列表会被替换成 `listOf("")` 占位**，否则 Room 生成 `IN ()` 让 SQLite 报语法错误。列别名刻意避开 SQLite 保留字 `current` 与语义撞名的 `income`。

聚合：`observeBuckets(format, start, end, income)`（`strftime` 分桶）、`observeCategories(start, end, income)`、`observeTotals(...)`。

## 3. 迁移链路

实际存在**三段历史演进**，按时间从旧到新：

```
① SharedPreferences("auto_ledger").getString("entries")  ── LedgerDbHelper.migrateFromPrefs
        │  (JSON 数组；INSERT OR REPLACE；成功后 prefs.remove("entries"))
        ▼
② ledger.db / entries 表（旧 SQLiteOpenHelper，列：id,amount,type,category,time_text,time_millis,note,source）
        │  LedgerDatabase.migrateLegacy（仅当 auto_ledger.db 是新文件时，读旧库→批量 insertAll 进 Room）
        ▼
③ auto_ledger.db / Bill 表（Room）
        │  MIGRATION_1_2：ALTER TABLE Bill ADD COLUMN external_id TEXT + CREATE UNIQUE INDEX
        │  MIGRATION_2_3：ALTER TABLE Bill ADD COLUMN is_recurring INTEGER NOT NULL DEFAULT 0 / recurring_rule TEXT
        ▼
      v3（当前）
```

要点：

- `LedgerDatabase.get()` 双检单例；`isNew = !auto_ledger.db.exists()`，**只有全新库**才触发 `migrateLegacy`（避免覆盖已有数据）。
- `migrateLegacy` 里的 `runBlocking` 是**刻意保留**：迁移发生在 Room 初始化线程（非主线程），不会 ANR；`RoomDatabase.Callback.onCreate` 非 suspend 只能同步落库（源码注释）。
- `MIGRATION_2_3` 两列都 `NOT NULL + DEFAULT`，老数据无需回填（`is_recurring=0` / `recurring_rule=NULL` 即"非周期"）；**不加索引**——模板个位数，全表扫代价可忽略，多索引会写放大。

## 4. 导入去重算法

两道闸门串联：

1. **`external_id` 唯一索引**（持久层）：`INSERT OR IGNORE`/`REPLACE` 语义由 `addImported` 控制，重复单号不落库。
2. **`ParseDedup`（`data/ParseDedup.kt:64`，内存层）**：仅在自动记账入口（短信/通知）调用，不碰手动记账 / CSV / 云恢复。
   - `WINDOW_MS = 5 * 60_000L`；`LinkedHashMap<String, Long> recent` 按插入序清理。
   - `fingerprint(amount, merchant, timeMillis)` = `"%.2f|%s|%d"`（金额两位定点 + 归一化商户 + `timeMillis / 60_000` 分钟数）。
   - `@Synchronized accept(fp, now)`：5 分钟内同指纹返回 `false`（丢弃）。
   - **取舍**：同一分钟、同金额、同商户的两笔真实消费会被合并成一笔。自动记账场景下"宁可少记让用户补，也不凭空多记让用户删"。

`addImported` 内部还有一层：拉全表已有行的 `externalId` 或 `fingerprint(timestamp, amount, type)` 建 key 集，逐条 `importKey()` 过滤 `distinctBy`——**单号优先、无单号用"毫秒时间+金额+收支"指纹**，返回实际新增数。

自动记账另有**跨渠道窗口**：`LedgerRepository.AUTO_IMPORT_WINDOW_MS = 2 * 60_000L`，`isRecentDuplicate(context, amount, type, source, timeMillis)` 只在窗口内找到「同金额 + 同收支 + **不同来源**」的自动账单时判重（同来源不合并，避免误杀真实的两笔同额消费）。`LedgerNotificationListener` 自身还有 `seen`（同通知 key 不重入）与 `merged`（**10 秒**窗口：渠道 + 方向 + 金额 + note 前 12 字）两道内存闸门，见 [03 §7](03-功能模块详解.md#7-通知监听记账--serviceledgernotificationlistenerkt247)。

## 5. 报表聚合（`data/ReportRepository.kt:190`）

`ReportAggregate(periodLabel, periodName, compareLabel, total, previousTotal, expense, income, trend: List<Bucket>, bars: List<Bucket>, categories: List<CategoryAgg>, dayCount)`。

- **周期计算** `periodRange(tab, offset, startDay)` 与 `observe` 同口径（供明细钻取）：tab 0=周（周日为起点，回退 `dow==SUNDAY? -6 : MONDAY-dow`，`-offset*7` 天）、1=月（`budgetMonthStart`）、2=年（1 月 1 日）。
- **自定义预算起始日** `budgetMonthStart(now, startDay, offset)`：`startDay.coerceIn(1,28)`；今天未到起始日则先回退一个月，再 `add(MONTH,-offset)`。`startDay=25` 即"上月 25 ~ 本月 24"。
- **标签**：月 `startDay==1` 显示"yyyy年M月"，否则**必须**显示真实区间"yyyy.MM.dd～MM.dd"（否则用户误以为自然月）。
- **一次扫描**：`observeTotals(cs,ce,ps,pe,outerStart=min,outerEnd=max,income)` 单次索引范围扫描拿本期/上期/支出/收入（旧实现 4 个独立 Flow，一次写库触发 4 次重查）。
- 图表：`combine(observeBuckets(trend), observeBuckets(bars), observeCategories)` + `combine(totals, charts)` → 最终 `ReportAggregate`。柱状固定最近 6 桶（周 -5 周 / 月 -5 月 / 年 -5 年）。

## 6. 线程与生命周期约束

- **DAO/仓库全 suspend 或返回 Flow**；写库统一在 `Dispatchers.IO` 协程。
- **广播/服务入口**：`SmsReceiver`、`ReminderReceiver` 用 `goAsync()` + 协程（广播 10s 超时前 `finish()`，`SmsReceiver` 用 `AtomicBoolean` 保证只调一次）。
- **`SimpleDateFormat` 非线程安全**：`LedgerGrouping` 的 `dayKeyFmt`/`clockFmt` 只在主线程/ViewModel 单协程使用；并行化须改 `java.time.DateTimeFormatter`。
- **`ValueAnimator.getDurationScale()`**：`LedgerApp` 读它，为 0（系统关动画）时把过渡时长设为 0。
- **`runBlocking` 唯一刻意用法**在 `migrateLegacy`（见 §3）。

## 7. 数据流全景（以"截屏记账"为例）

```
[用户点磁贴 / 浮动入口]
   └─ ScreenshotTileService / LedgerApp 扫一扫
        ├─ 无障碍路径：ScreenshotAccessibilityService.capture()（8s 超时兜底）
        └─ MediaProjection 路径：ScreenshotRequestActivity 授权 → ScreenshotCaptureService
                → ImageReader/VirtualDisplay 抓帧（latch.await 4s 超时）
        ▼
   Bitmap → PNG(85) → Base64 → VisionHelper.callVisionModel(prefs, b64)
        │  (OpenAI 兼容 chat/completions，prompt = prefs.aiPrompt)
        ▼
   解析 JSON → NotifyBill → VisionHelper.postResult 发结果通知（「记一笔 / 忽略」）
        ▼
   ConfirmEntryReceiver → LedgerRepository.addImported → Room Bill（external_id 去重）
        ▼
   HomeViewModel 的 observePaging Flow 自动刷新首页列表
```

三条采集链最终都收敛到 `LedgerRepository.addImported`，再各自经 `BillNotifier`（通知/短信）或 `VisionHelper.postResult`（截屏）发可撤销/可确认的通知，形成统一的入库与回执闭环。
