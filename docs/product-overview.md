# 产品概览

## 1. 产品定位

AutoLedger 是一款 Android 本地优先记账工具，核心目标是把支付通知、短信和账单截图中的交易快速转换为可核对、可统计的账目。

产品围绕三个原则设计：

1. **自动采集**：尽可能减少手工输入。
2. **本地可控**：账单和设置默认保存在设备，不要求账号或自有服务器。
3. **可审计**：自动结果可以查看来源、二次确认、编辑和撤销。

## 2. 目标用户

- 频繁使用微信、支付宝、银行卡且通知较多的个人用户。
- 希望保留本地数据、不依赖商业记账云服务的用户。
- 需要按周、月、年观察支出结构和预算进度的人。
- 能自行配置 OpenAI 兼容模型或 WebDAV 服务的高级用户。

## 4. 用户路径

### 4.1 首次使用

1. 安装并打开应用。
2. 授予通知权限。
3. 在“设置 -> 权限与后台”授权通知使用权。
4. 按需开启短信权限、无障碍截图、电池白名单和精确闹钟。
5. 在“设置 -> AI 与高级功能”配置模型地址、Key、模型名和可选 Prompt。
6. 在“设置 -> 数据与备份”配置 WebDAV。

通知使用权、短信和无障碍均按需授权。未授权的通道不会阻止手动记账。

### 4.2 手动记账

1. 进入“记一笔”。
2. 选择收入或支出。
3. 输入金额并选择分类、子分类和时间。
4. 按需添加备注或周期规则。
5. 保存后返回首页列表。

### 4.3 自动记账

1. 系统通知或短信进入应用。
2. 全局词库先决定强制放行或拦截。
3. 用户规则优先于系统规则。
4. 内置解析作为最后兜底。
5. 自动结果经过跨来源合并、转账配对和唯一键去重后入库。
6. 用户可在结果通知中撤销。

### 4.4 AI 识图

1. 从首页选择相册、拍照或截图磁贴。
2. 图片发送到用户配置的视觉模型。
3. 客户端清洗模型响应并解析全部交易。
4. 本地分类引擎再次校正分类。
5. 结果通知展示单笔或多笔汇总。
6. 用户确认后才批量写入账单。

## 5. 信息架构

主界面固定三个底部页签：

- 记账
- 记一笔
- 报表

设置页和搜索页作为覆盖层打开，不修改三页签主结构。设置页按功能分为自动记账、记账设置、通知与提醒、数据与备份、外观与小部件、AI 与高级功能、权限与后台、关于。

## 6. 数据与隐私边界

- 账单数据库：本地 Room `auto_ledger.db`。
- 普通配置与二级分类：本地 SharedPreferences。
- 敏感凭据：Android Keystore 加密存储。
- AI：文本或图片发送到用户配置的 Endpoint。
- WebDAV：账目 JSON 上传到用户配置的服务器。
- 应用没有自有账号、广告 SDK 或行为分析 SDK。

实现细节见 [安全与隐私](security-and-privacy.md)。

## 7. 当前边界

- 一级分类是推断契约的一部分，用户只维护二级分类。
- LSPosed 入口是骨架，未实现 Hook 自动授权或系统级采集。
- 交易日期由模型文本和本地解析器估定，应允许用户确认或修改。
- 部分金融页面禁止截图，此时只能使用相册上传。
- CSV/XLSX 面向数据交换，不完整保留内部转账元数据。WebDAV JSON 备份会保留。

## 8. 成功标准

- 正常通知和短信可稳定生成账单，重复投递不会重复入账。
- 自动分类优先命中明确商户，歧义场景回退“其他”。
- 内部转账保留在列表中，但不抬高收入、支出和分类占比。
- AI 输出格式异常时 UI 只显示稳定错误文案，原始响应只进入 Logcat。
- 所有数据写入通过 Repository 或 DAO，界面不直接操作数据库。
