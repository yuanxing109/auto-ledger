# 06 · 全局 UI 统一改造方案

> **状态：P0 已全部落地（2026-11-21 起）**，本文的设计规范（§2）已成为代码真源并被 `tools/check-ui-consistency.sh` 门禁守护。
> §1「现状问题清单」是**改造前的快照**，保留作背景；§2 的 token 数值已按 `ui/theme/LedgerPalette.kt`、`LedgerDimens.kt`、`LedgerTextStyles.kt` 的**实际值**校正（旧的草案数值已更新）。

## 0. 结论摘要

- 全站三类真源：**色 → `LedgerPalette`**、**尺寸/圆角 → `LedgerDimens`**、**字号 → `LedgerTextStyles`（14 个 Miuix 槽）**。任何页面不得再写 `Color(0x…)`、魔法 `fontSize`、非阶梯 `RoundedCornerShape`。
- 唯一主题根：`ui/theme/AppTheme.kt` 的 `AppTheme()`，全站只在 `LedgerApp` 调用一次。页面里禁止再包 `MiuixTheme` / `MaterialTheme`。
- 玻璃体系**已退役**：`GlassHost` 只作根容器背景层，内容层全部实心 `surface` + 1dp `borderSoft`。
- 门禁 `tools/check-ui-consistency.sh` 7 条规则，CI 在编译前执行（见 [`04`](04-开发与扩展指南.md) §3、§8）。

## 1. 现状问题清单（改造前快照，仅供背景）

### A. 深色模式未适配 / 半适配

- 自绘 `Canvas` 图表、部分卡片硬编码浅色值，切深色后出现「浅底 + 深字」或「深底 + 深字」。
- 曾存在**两套色源**（`LedgerTheme` 自绘色 + Miuix `Colors`），同一屏两侧深浅不一致。

### B. 全局风格不统一

- 间距随手写 14dp / 13dp / 20dp；字号随手写 12/15/18sp；圆角随手 6/10/18dp，无阶梯。
- 有 43 处 `Toast.makeText`，与 Miuix 的 Snackbar 反馈不一致。

### C. 设计缺陷（需重做而非统一）

- 搜索页筛选器铺在主界面，信息密度失控 → 改为主界面五区 + 筛选 BottomSheet（§4）。
- `indication = null` 去掉点击涟漪但没给替代反馈，操作"没手感"。

### 2.2 字号阶梯（Miuix 14 槽，一槽一档）

> 真源：`ui/theme/LedgerTextStyles.kt` 的 `ledgerTextStyles()`，用 `defaultTextStyles(...)` 逐槽覆盖 Miuix 的 14 个 `textStyles`。页面只允许 `MiuixTheme.textStyles.xxx`，禁止自写 `fontSize = 13.sp`（R4/R5 统计）。字体族暂用系统默认，LXGW 文楷接入点是各槽 `fontFamily`（数字组永不换字体）。

### 2.3 间距与圆角

> 真源：`ui/theme/LedgerDimens.kt`。阶梯只有五档，`R6` 会统计阶梯外的魔法圆角（现 warn，迁移完成后升 error）。

| 类别 | Token | 值 |
| --- | --- | --- |
| 间距 | `xs / sm / md / lg / xl / xxl` | 4 / 8 / 12 / 16 / 24 / 32 dp |
| 最小触摸目标 | `minTouch` | 48 dp |
| 圆角 | `radiusSm / radiusMd / radiusLg / radiusXl / radiusDialog` | 8 / 12 / 16 / 24 / 28 dp |
| 圆角合法阶梯（R6 白名单） | — | 4 / 8 / 12 / 16 / 24 / 32 / 50 dp |
| 胶囊 | `radiusCapsule` | 50 dp |
| 卡片 / 页面内边距 | `cardPadding / pagePadding` | 16 / 16 dp |
| 卡间距 | `gap / gapSmall / gapLarge` | 12 / 8 / 24 dp |

组件用 `LedgerDimens.default` 实例（卡片圆角 = `radiusXl` = 24dp，Sheet 圆角 = `radiusDialog` = 28dp，小圆角 = `radiusMd` = 12dp）。

### 2.4 组件规范

- 卡片：`surface` 底 + 1dp `borderSoft` 边 + `radiusXl`（24dp）圆角 + `cardPadding`(16dp) 内边距。
- 可点击行 / chip / 输入框：边界用 `border`（≥3:1），圆角走阶梯。
- 反馈：统一 Miuix Snackbar（`ui/window/LedgerSnackbar.kt` 的 `LedgerSnackbar` / `LocalSnackbar`），Composable 内禁止 `Toast.makeText`（R7）。Receiver/Service 等非 Composable 宿主例外。
- 图标优先 `MiuixIcons`，缺失的放 `ui/AiScanIcon.kt` 同目录的风格化图标。

### 2.5 金额排版

- 金额一律 `tnum` 等宽数字，避免跳动；大号金额用 `amountDisplayStyle()`（34sp）。
- 红/绿只表示支出/收入，且必须配 `+ / −` 号或「收入/支出」文字（色盲友好）。

## 4. 搜索页重新设计

### 4.1 旧方案的问题

筛选器（类型/金额/日期/分类）平铺主界面，占掉首屏大半，输入框反被挤小；空结果时无引导。

### 4.2 新信息架构（五区）

1. 顶部：搜索框（关键词）
2. 类型 Chips：全部 / 支出 / 收入 / 其他
3. 金额区间：最小值 / 最大值
4. 日期区间：预设（今天/本周/本月/今年）+ 自定义
5. 分类多选

主界面只看五区入口 + 结果列表；重型筛选收进 `FilterSheet`（BottomSheet）。实现落点见 `ui/screen/SearchScreen.kt`（`FilterSheet` L597、`Chip` L482、`AmountBox` L507、结果按天分组 `DayHeader` L466 / `ResultRow` L543）。

### 4.3 分区与交互

- 结果按天分组，每天头行显示当日支出合计。
- 改筛选即刷新（`LedgerRepository.search` / `countSearch`），结果上限默认 300 条。

### 4.4 筛选 BottomSheet

把类型 / 金额 / 日期 / 分类全部搬进 `FilterSheet`，主界面只留搜索框 + 类型 Chips + 结果。

### 4.5 代码落点

`ui/screen/SearchScreen.kt`：`SearchScreen`(L98) → `resetFilters`(L157) → 各筛选子组件 → `FilterSheet`(L597)。

## 5. 需求 4 的两处具体改法（历史，已落地）

- 「比上月少」文案/配色：语义上"少花"是好消息但也属支出对比，统一用 `textSecondary` 中性色，不误用绿色。
- 记账金额加粗：主金额走 `amountDisplayStyle()`（34sp Bold tnum），列表金额走 `headline2`（28sp）。

## 8. 验收清单（= `tools/check-ui-consistency.sh`）

| 规则 | 内容 | 级别 |
| --- | --- | --- |
| R1 | `MiuixTheme(` / `MaterialTheme(` 只允许出现在 `ui/theme/AppTheme.kt` | error |
| R2 | 禁止 `Color(0x…)` 字面量（豁免 `ui/theme/`、`data/CategoryStore.kt`、`ui/LedgerTheme.kt`） | error |
| R3 | 禁止 `Color.White/Black/…` 命名色（豁免 `ui/theme/`、`ui/AiScanIcon.kt`） | error |
| R4 | 字号只走 `MiuixTheme.textStyles`，禁止 `fontSize = N.sp`（豁免 `ui/theme/`） | warn |
| R5 | 字重只走 textStyles，禁止裸 `fontWeight = FontWeight.*`（豁免 `ui/theme/`） | warn |
| R6 | 圆角只用合法阶梯 4/8/12/16/24/32/50（细线豁免：高度≤6dp 时圆角可为高度一半） | warn |
| R7 | 不新增 `Toast.makeText`（非 Composable 宿主例外） | warn |

用法：`bash tools/check-ui-consistency.sh`，退出码 0=通过（warn 不阻断），1=有 error 级违规。CI 在 `assembleDebug` 之前执行（见 `.github/workflows/android.yml`）。
